02

Constraint'lar — bazaning o'zi qo'riqchi

Java kodida tekshirish yaxshi, lekin bazaga 5 xil servis yozadi. Constraint — oxirgi chegara: qoidani buzgan satr hech qachon kirmaydi. Qiymatlarni o'zgartirib, INSERT qiling.

Natija shu yerda.
V1__hisob.sql
CREATE TABLE hisob (
    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,  -- serial o'rniga zamonaviy usul
    raqam     char(20) NOT NULL UNIQUE,
    mijoz_id  bigint NOT NULL REFERENCES mijoz(id),
    valyuta   char(3) NOT NULL DEFAULT 'UZS',
    balans    numeric(18,2) NOT NULL DEFAULT 0 CHECK (balans >= 0),
    ochilgan  timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT uq_mijoz_valyuta UNIQUE (mijoz_id, valyuta)   -- bir mijozda bir valyutada bitta hisob
);
💡 Java tomonda
Constraint buzilsa JDBC SQLException → Spring DataIntegrityViolationException. Uni @ExceptionHandler'da ushlab 409 Conflict qaytaring. Lekin UNIQUE'ga tayanib "avval SELECT, keyin INSERT" yozmang — ikki so'rov orasida boshqa tranzaksiya kirishi mumkin (race). INSERT qiling, xatoni ushlang, yoki ON CONFLICT DO NOTHING.

Foreign key va ON DELETE — mijoz o'chsa nima bo'ladi?

FK ikki jadvalni bog'laydi. Ota yozuv o'chirilganda bola yozuvlar taqdiri ON DELETE qoidasiga bog'liq. Rejimni tanlab, mijozni o'chiring.

mijozPK id
hisobFK mijoz_id
Mijozni tanlang (chapda) va o'chiring.
⚠ Bankda
Moliyaviy yozuvlar (hisob, tranzaksiya) hech qachon CASCADE bilan o'chmasin — audit talab. Odatda umuman o'chirilmaydi: holat = 'YOPILGAN' (soft delete). CASCADE — faqat haqiqiy "bola" ma'lumot uchun (masalan, buyurtma → buyurtma qatorlari).

07

Suhbat savollari

?PRIMARY KEY va UNIQUE farqi?›
Ikkalasi ham takrorlanmaslikni kafolatlaydi va avtomatik indeks yaratadi. PK: jadvalda bitta, NULL bo'lmaydi, FK'lar unga ishora qiladi. UNIQUE: bir nechta bo'lishi mumkin, NULL'ga ruxsat (va bir nechta NULL — PostgreSQL'da NULL ≠ NULL). Pul/biznes kaliti (hisob raqami) — UNIQUE, texnik id — PK.
?Pul uchun qaysi tip? Nega float emas?›
numeric(18,2) — o'nlik aniq. float/double ikkilik — 0.1 aniq ifodalanmaydi, yig'indi xatolari to'planadi. Java'da BigDecimal bilan juft. Muqobil: tiyinlarda bigint.
?serial, identity, uuid — qaysi biri?›
serial — eski (sequence + default, ownership muammolari). GENERATED ALWAYS AS IDENTITY — SQL standarti, tavsiya. uuid — tarqoq tizimlar, mijoz tomonda yaratish, id'ni taxmin qilib bo'lmaydi; kamchilik: 16 bayt, indeks tasodifiy (fragmentatsiya) — UUIDv7 yechadi.
?timestamp va timestamptz farqi?›
timestamptz UTC'da saqlaydi, sessiya zonasiga qarab ko'rsatadi — DST va ko'p zonali tizimda to'g'ri. timestamp — "devordagi soat", zona yo'q. Deyarli har doim timestamptz. Java: Instant / OffsetDateTime.
?FK ustuniga indeks avtomatik yaratiladimi?›
Yo'q! PK va UNIQUE'ga — ha, FK'ga — yo'q. FK'siz indeks: ota yozuvni o'chirish/yangilashda bola jadval to'liq skan bo'ladi, JOIN'lar sekin. Har FK'ga CREATE INDEX — odat qiling.
?Normalizatsiya nima, qachon denormalizatsiya qilasiz?›
Takrorlanishni yo'qotish, har fakt bir joyda (1NF: atomar qiymatlar; 2NF: kalitga to'liq bog'liqlik; 3NF: kalit bo'lmagan ustunlar bir-biriga bog'liq emas). Denormalizatsiya — o'qish tezligi uchun ataylab takrorlash (hisobot jadvallari, cache ustunlar), yozishda sinxronlash mas'uliyati bilan.
