Klass va obyekt

Java butunlay obyektlarga qurilgan. Class — bu chizma (uy loyihasi). Obyekt — o'sha chizma bo'yicha qurilgan real uy. Bitta chizmadan minglab uy chiqadi, har biri mustaqil.

01

Class — holat + xatti-harakat

Class ikki narsani birlashtiradi: maydonlar (fields — "qanaqa") va metodlar (behavior — "nima qila oladi"). Rangli qismlarni bosing.

Mashina.java
public class Mashina {
    String rusum;
    int tezlik;

    Mashina(String r) {   // konstruktor
        this.rusum = r;
        this.tezlik = 0;
    }

    void tezlashtir() {
        tezlik = tezlik + 10;
    }
}
02

Obyekt fabrikasi — new

new Mashina("...") chizmadan real obyekt yaratadi va uni Heap'ga joylaydi. Tugmani bosing — har bosishda yangi, mustaqil mashina paydo bo'ladi. Birini tezlashtiring — boshqasi o'zgarmaydi.

class Mashina — chizma (bitta)
class Mashina { String rusum; int tezlik = 0; }
Heap — obyektlar (ko'p, mustaqil)
Hali obyekt yo'q. Tugmani bosing ↑
Bitta classdan cheksiz obyekt yasash mumkin. Har biri Heap'da alohida joy va o'z maydon qiymatlariga ega.
03

this — "aynan shu obyekt"

Konstruktor ichida this.rusum yozdik. this — "hozir yaratilayotgan aynan shu obyekt". Parametr r bilan maydon rusumni ajratish uchun kerak (ular bir xil nomli bo'lsa). Har obyektning o'z this'i bor.

This.java
Mashina(String rusum) {
    this.rusum = rusum;  // this.rusum = maydon, rusum = parametr
}
// this bo'lmasa: rusum = rusum; — parametr o'ziga o'zini bergan bo'lardi (xato mantiq)
konstruktor zanjiri
Bitta konstruktor boshqasini this(...) orqali chaqirishi mumkin (constructor chaining) — takrorni kamaytiradi. Masalan Mashina() ichida this("Noma'lum").
04

static vs instance maydon — jonli farq

Bu suhbatda tez-tez so'raladi. instance maydon — har obyektda alohida nusxa. static maydon — butun class uchun bitta, hamma obyektlar bo'lishadi. Obyekt yarating va farqni ko'ring: har birining o'z id'si bor, lekin count hammaga umumiy.

class Hisoblagich (static — umumiy) static count = 0
Hali obyekt yo'q ↓
Har new da: obyekt o'z id'sini oladi (alohida), va static count bittaga oshadi (umumiy). Yaratib ko'ring.
Hisoblagich.java
class Hisoblagich {
    static int count = 0;  // UMUMIY — class'ga tegishli
    int id;                // ALOHIDA — har obyektga tegishli

    Hisoblagich() {
        count++;            // umumiy hisob oshadi
        id = count;         // bu obyekt o'z raqamini oladi
    }
}
suhbatda
"static maydon qayerda saqlanadi?" — obyektda emas, class darajasida (Metaspace/Method Area). Shuning uchun obyektsiz ham mavjud va hamma obyektlar bir nusxani bo'lishadi. Hisoblagich.count deb class orqali kirasiz.
05

Encapsulation — himoyalash (kirish)

Maydonlarni private qilib, faqat metodlar orqali o'zgartirishga ruxsat berish. Bu keyingi modulda chuqur ochiladi — hozircha g'oya: metod ichida tekshirish qo'yasiz, ochiq maydonga esa har qanday qiymat kelishi mumkin.

Hisob.java
private int balans;         // tashqaridan to'g'ridan o'zgartirib bo'lmaydi

public void yech(int s) {
    if (s <= balans)          // qoida shu yerda himoyalanadi
        balans -= s;
}
06

Suhbat savollari

?Class va obyekt farqi?
Class — ta'rif/chizma (bir marta yoziladi). Obyekt — new bilan undan yasalgan real nusxa (istagancha). Class xotira egallamaydi, obyekt Heap'da joy oladi. Class — retsept, obyekt — pishirilgan taom.
?static va instance maydon farqi?
instance — har obyektda alohida nusxa (har mashinaning o'z tezligi). static — butun class uchun bitta, hamma obyektlar bo'lishadi (umumiy hisoblagich). static class orqali chaqiriladi, instance obyekt orqali.
?Konstruktor nima va default konstruktor?
Konstruktor — obyekt yaratilganda ishga tushadigan maxsus metod (nomi class bilan bir xil, return tipi yo'q). Agar hech qanday konstruktor yozmasangiz, Java bo'sh default konstruktor qo'shadi. Lekin bitta konstruktor yozsangiz, default yo'qoladi.
?this nima uchun kerak?
Joriy obyektga ishora qiladi. Asosan parametr va maydon bir xil nomli bo'lganda ularni ajratish uchun (this.rusum = rusum), yoki bir konstruktordan boshqasini chaqirish uchun (this(...)).

Keyingi modul

Encapsulation va access modifiers

private, public, protected, default — kim nimaga kira oladi. getter/setter, immutable class va nega maydonlarni yashirish yaxshi dizayn. Bank hisobi misolida ko'ramiz.
