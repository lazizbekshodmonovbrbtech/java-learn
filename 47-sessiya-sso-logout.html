Sessiya, SSO va logout

Login'ni hamma tushunadi, logout'ni esa deyarli hech kim. Kassir "Chiqish"ni bosdi, lekin qaytib kirganda parol so'ralmadi. Nega? Admin xodimni blokladi, lekin u yana 5 daqiqa ishladi. Nega? Javob bitta: tizimda uch qatlam sessiya bor. Laboratoriyada uchalasini ko'rasiz.

01

Uch qatlam — uch xil "sessiya"

🔐
Keycloak SSO sessiyasi

auth.bank.uz domenidagi cookie: KEYCLOAK_IDENTITY, KEYCLOAK_SESSION

"Bu brauzer kimniki". Bor ekan, istalgan ilova login so'rasa — parolsiz, darhol kod beriladi. Idle/Max muddatlari bor.

🏦
Ilova sessiyasi

ib.bank.uz domenidagi cookie: JSESSIONID (yoki BFF sessiyasi)

"Bu ilova foydalanuvchini taniydi". Ichida tokenlar saqlanadi. Keycloak'dan mustaqil — o'z-o'zidan o'chmaydi.

🎫
Access token

API'larga Bearer — stateless

"Bu so'rovga ruxsat bor" — exp'gacha. API sessiya haqida hech narsa bilmaydi va hech kimdan so'ramaydi.

🎯 Suhbatda
"SSO qanday ishlaydi?" — Keycloak o'z domenida SSO cookie qo'yadi. Ikkinchi ilova foydalanuvchini /auth'ga yo'naltirganda, brauzer shu cookie'ni yuboradi, Keycloak sessiyani taniydi va login formasini ko'rsatmasdan darhol kod bilan qaytaradi. Har ilova baribir o'z Authorization Code flow'idan o'tadi — faqat parol qadami tushib qoladi.

04

"Logout qildim, token baribir ishlayapti" — yechimlar

1. Qisqa access token

5 daqiqa. Eng oddiy va asosiy himoya. Refresh token Keycloak'da tekshiriladi, sessiya yo'q bo'lsa — rad etiladi.

2. Sezgir operatsiyada introspection

O'tkazma, limit o'zgartirish kabi operatsiyalarda /token/introspect — Keycloak "active: false" deydi. Qolgan joyda lokal JWT tekshiruvi.

3. Gateway'da sid/jti blacklist

Back-channel logout kelganda sid'ni Redis'ga (TTL = token lifespan) yozish; gateway har so'rovda tekshiradi. Arzon va tez.

4. Not-before policy (revocation)

Realm/Client → Revocation → "Set to now" + "Push": shu vaqtdan oldin chiqarilgan barcha tokenlar yaroqsiz (favqulodda holat uchun).

05

Offline token va "Remember me"

Offline token

scope=offline_access bilan so'raladi. SSO sessiya tugagandan keyin ham ishlaydigan refresh token (Offline Session Idle, default 30 kun). Mobil ilovada "har safar parol so'ramaslik" uchun. Xavf: telefon o'g'irlansa, token uzoq yashaydi — biometrik qulf va qurilmani bog'lash kerak. Admin Users → Consents/Sessions'dan bekor qiladi.

Remember me

Realm → Sessions: "Remember me" belgilansa, SSO sessiya brauzer yopilgandan keyin ham qoladi, alohida (uzunroq) Idle/Max bilan. Internet-bank uchun odatda o'chiq.

💡 Keycloak 26: persistent sessions
26-versiyadan boshlab foydalanuvchi sessiyalari sukut bo'yicha bazada ham saqlanadi (persistent user sessions). Keycloak qayta ishga tushirilganda yoki yangilanganda foydalanuvchilar "chiqib ketmaydi". Eski versiyalarda sessiyalar faqat Infinispan xotirasida edi.
06

Suhbat savollari

?Foydalanuvchi logout qildi, lekin "Kirish"ni bosganda parolsiz kirdi. Nega?›
Faqat ilovaning lokal sessiyasi yopilgan, Keycloak SSO sessiyasi (auth domenidagi cookie) tirik. Yangi /auth so'rovi SSO cookie bilan keladi va darhol kod qaytadi. Yechim: RP-initiated logout — end_session_endpoint'ga id_token_hint bilan yo'naltirish.
?Back-channel logout qanday ishlaydi?›
Keycloak sessiya tugaganda (logout, admin, muddat) sessiyada qatnashgan har client'ning Backchannel logout URL'iga server'dan POST yuboradi. Body'da imzolangan logout_token (JWT) bo'ladi: iss, aud, sid, events. Ilova imzoni tekshiradi va shu sid'ga bog'langan sessiyani o'chiradi. Brauzer ishtirok etmaydi — shuning uchun ishonchli.
?Admin xodimni blokladi. Qancha vaqtda kirish yopiladi?›
Yangi login va refresh — darhol rad etiladi. Ilova sessiyalari — back-channel logout sozlangan bo'lsa darhol, aks holda keyingi refresh'da. Stateless API'larda mavjud access token — exp'gacha (5 daq). Kerak bo'lsa: not-before push, introspection yoki gateway'da sid blacklist.
?SSO Session Idle va Access Token Lifespan farqi?›
Idle — foydalanuvchi faolligisiz qancha vaqtdan keyin Keycloak SSO sessiyasi tugaydi (har refresh/login uni yangilaydi). Access lifespan — bitta access tokenning umri. Idle tugasa — refresh ham ishlamaydi, qayta login kerak. SSO Session Max — faollikdan qat'i nazar maksimal umr.
?Offline token qachon ishlatiladi, xavfi nima?›
SSO sessiyadan mustaqil, uzoq yashaydigan refresh token — mobil ilova, fon jarayonlari va integratsiyalar uchun. Xavfi: o'g'irlansa, uzoq ishlaydi. Himoya: qurilmaga bog'lash, biometriya, rotation, "Offline Session Max" limiti, shubhali holatda revoke.
