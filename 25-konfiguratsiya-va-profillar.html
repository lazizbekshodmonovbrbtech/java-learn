Konfiguratsiya va profillar

Bitta jar — uch muhit: dasturchi noutbuki, test stendi, prod. Kod bir xil, sozlamalar har xil. Bu modulda "qaysi sozlama kimni yengadi" degan savolga jonli javob olasiz.

01

Sozlamalar ustunligi: kim kimni yengadi?

Bitta xususiyat — bank.limit — 5 joyda berilgan bo'lishi mumkin. Spring aniq tartibda o'qiydi: yuqoridagi pastdagini yengadi. Qatlamlarni o'chirib-yoqing, natijani kuzating.

bank.limit = —
Amaliy qoida
Kodga (yml) — defaultlar; muhitga (env var, Kubernetes ConfigMap/Secret) — farqlar va sirlar. Parolni hech qachon yml'ga yozmang — ${DB_PASSWORD} placeholder qo'ying, qiymatni muhit beradi.
02

Profillar: dev / test / prod

Profil — nomlangan sozlamalar to'plami + shartli bean'lar. application-{profil}.yml fayli avtomatik yuklanadi, @Profile("prod") bean'lari faqat shu profilda yaratiladi. Profilni tanlang:

dev
test
prod

Yuklanadigan fayllar

Yaratiladigan bean'lar

SmsConfig.java · faollashtirish
@Bean @Profile("prod")          SmsYuboruvchi real()  { return new PlaynetSms(); }
@Bean @Profile("!prod")         SmsYuboruvchi soxta() { return xabar -> log.info("SMS: {}", xabar); }

// Faollashtirish (ustunlik tartibida):
// java -jar app.jar --spring.profiles.active=prod
// SPRING_PROFILES_ACTIVE=prod  (Docker/K8s — odatiy usul)
// application.yml: spring.profiles.active: dev  (faqat lokal default uchun)
// Test: @ActiveProfiles("test")
// Bir nechta: prod,metrics — ikkalasi ham faol
03

YAML → Java: @ConfigurationProperties

@Value("${...}") — bitta qiymat uchun. Guruh sozlamalar uchun tipli klass: validatsiya, IDE yordami, refaktoring. YAML qatorini bosing — Java'da qayerga tushishini ko'ring.

bank:   limit-max: 50000000   valyuta: UZS   sms:     url: https://sms.uz/api     timeout: 3s   ruxsat-ip: [10.0.0.1, 10.0.0.2]
@ConfigurationProperties(prefix = "bank") @Validated public record BankProps(   @Positive long limitMax,   @NotBlank String valyuta,   Sms sms,   List<String> ruxsatIp ) {   record Sms(URI url, Duration timeout) {} }
Bosing. limit-max (kebab) → limitMax (camel) — "relaxed binding". 3s → Duration, ro'yxat → List. Xato bo'lsa startup'da yiqiladi — prod'da noto'g'ri sozlama bilan ishlab ketmaydi.
Ishlatish
@SpringBootApplication
@ConfigurationPropertiesScan          // yoki @EnableConfigurationProperties(BankProps.class)
class App {}

@Service
class TolovService {
    private final BankProps props;              // oddiy bean kabi inject
    boolean ruxsat(long s) { return s <= props.limitMax(); }
}

// @Value — bitta qiymat, default bilan:
@Value("${bank.valyuta:UZS}") String valyuta;
// Fark: @Value — string, validatsiya yo'q, IDE yordam bermaydi, sochilib ketadi.
04

Relaxed binding va muhit o'zgaruvchilari

Muhit o'zgaruvchisida nuqta va tire bo'lmaydi. Spring bularni bir xil deb tushunadi:

bank.limit-max=bank.limitMax=bank.limit_max=BANK_LIMITMAX=BANK_LIMIT_MAX

Sirlar (secrets) — to'g'ri

spring:
  datasource:
    url: jdbc:postgresql://${DB_HOST}:5432/bank
    username: ${DB_USER}
    password: ${DB_PASSWORD}
# qiymat: K8s Secret / Vault / .env (gitignore)
Placeholder yml'da, qiymat muhitda. Spring Cloud Vault / AWS Secrets Manager bilan avtomatik.

Noto'g'ri

# @Value("${password}") ni log'ga chiqarish

05

Suhbat savollari

?Spring Boot sozlamalarni qaysi tartibda o'qiydi?
Yuqoridan pastga ustunlik: buyruq qatori argumentlari → SPRING_APPLICATION_JSON → JVM -D → OS muhit o'zgaruvchilari → application-{profile}.yml/properties (jar tashqarisidagi, keyin ichidagi) → application.yml → @PropertySource → default. Xuddi shu kalit yuqoridagida bo'lsa, pastdagi ustidan yoziladi. Profil fayli oddiy fayldan ustun.
?@Value va @ConfigurationProperties farqi?
@Value — bitta kalit, SpEL qo'llaydi, string→tip oddiy konvertatsiya, validatsiya yo'q, sozlamalar kod bo'ylab sochiladi. @ConfigurationProperties — prefiks bo'yicha butun guruh tipli klass/record'ga, relaxed binding, nested obyekt/ro'yxat, Duration/DataSize, @Validated bilan startup validatsiya, IDE metadata (spring-boot-configuration-processor). Guruh sozlamalar uchun — ikkinchisi.
?Profil nima? Qanday faollashtiriladi?
Muhitga mos sozlama to'plami va shartli bean'lar. application-{name}.yml avtomatik, @Profile('x')/@Profile('!x') bean'lar. Faollashtirish: spring.profiles.active (yml'da faqat lokal default), SPRING_PROFILES_ACTIVE env, --spring.profiles.active=, testda @ActiveProfiles. Bir nechta profil vergul bilan; spring.profiles.group bilan guruhlash; 'default' profil hech biri berilmaganda.
?Sirlarni (parol, token) qanday saqlaysiz?
Yml'da placeholder: ${DB_PASSWORD}. Qiymat — muhit o'zgaruvchisi (Docker secret, K8s Secret mounted env), yoki Spring Cloud Vault / AWS Secrets Manager / Azure Key Vault (spring.config.import=vault://). Git'ga hech qachon. Log'ga chiqmasin (Actuator /env sanitize qiladi). Prod parol lokalga tushmasin.
?Relaxed binding nima?
Bitta xususiyatni turli yozuvda berish mumkinligi: bank.limit-max (yml, tavsiya), bank.limitMax, bank.limit_max, BANK_LIMITMAX / BANK_LIMIT_MAX (env). Env var'da nuqta va tire bo'lmagani uchun kerak. Ro'yxat: BANK_HOSTS_0, BANK_HOSTS_1.
?application.properties va yml farqi? Ikkalasi bo'lsa?
Sintaksis: properties — kalit=qiymat, tekis; yml — ierarxik, ro'yxatlar qulay, lekin bo'shliqqa sezgir va bir faylda '---' bilan bir nechta hujjat (profil bo'yicha) bo'lishi mumkin. Ikkalasi bo'lsa properties yml'dan ustun. Jamoada bittasini tanlang.
?Sozlama o'zgarganda restart'siz qo'llash mumkinmi?
Oddiy Boot'da yo'q — startup'da o'qiladi. Spring Cloud Config + @RefreshScope (actuator/refresh) yoki Consul/Kubernetes ConfigMap watcher bilan. @ConfigurationProperties bean'lari @RefreshScope'siz ham Cloud Config'da qayta bog'lanadi. Bank tizimida odatda deploy orqali — o'zgarish audit qilinadi.
?Testda konfiguratsiyani qanday o'zgartirasiz?
@SpringBootTest(properties = "bank.limit=100"), @TestPropertySource, @ActiveProfiles("test") + application-test.yml, @DynamicPropertySource (Testcontainers port kabi dinamik qiymatlar uchun), @MockBean bilan bean almashtirish.
