Optional

null — "milliard dollarlik xato" (uni ixtiro qilgan olimning o'z so'zi). NullPointerException Java'dagi eng ko'p uchraydigan xato. Optional "qiymat bor yoki yo'q"ni aniq ifodalaydi va tekshirishga majburlaydi.

01

Muammo: null zanjirlari

Null.java
// ❌ Har qadamda NPE xavfi
String shahar = user.getManzil().getShahar().toUpperCase();
// user null? manzil null? shahar null? — istalgani 💥

// ❌ Himoya — lekin o'qib bo'lmaydi
if (user != null && user.getManzil() != null
    && user.getManzil().getShahar() != null) { ... }

// ✓ Optional bilan — toza zanjir
String shahar = Optional.ofNullable(user)
    .map(User::getManzil)
    .map(Manzil::getShahar)
    .map(String::toUpperCase)
    .orElse("NOMA'LUM");
02

Zanjir — qiymat bor va yo'q holatda

Optional — qiymat bo'lishi ham, bo'lmasligi ham mumkin bo'lgan quti. Zanjirdagi har amal quti to'la bo'lsa ishlaydi, bo'sh bo'lsa — o'tkazib yuboriladi va oxirida default beriladi. Tugmani almashtirib ko'ring.

user mavjud:
Ha (Otabek, Toshkent)
asosiy g'oya
Quti bo'sh bo'lsa, map/filter hech narsa qilmaydi — bo'sh qutini uzatadi. NPE hech qachon chiqmaydi. Oxirida orElse bo'shlikni default bilan to'ldiradi.
03

Asosiy metodlar

Optional.of(x)
x null bo'lmasa (aks holda NPE)
Optional.ofNullable(x)
x null bo'lishi mumkin
Optional.empty()
bo'sh quti
map(f)
ichini o'zgartirish
filter(p)
shartga mos bo'lmasa bo'shatish
orElse(default)
bo'sh bo'lsa default
orElseThrow(...)
bo'sh bo'lsa exception
ifPresent(c)
bor bo'lsa bajar
isPresent() / isEmpty()
tekshirish (kam ishlating)
04

To'g'ri va noto'g'ri ishlatish

Optional — metod qaytish qiymati uchun yaratilgan ("natija bo'lmasligi mumkin"). Boshqa joylarda ishlatish — anti-pattern.

❌ get() to'g'ridan

opt.get();  // bo'sh bo'lsa NPE!
Optional'ning maqsadini yo'qqa chiqaradi. orElse/orElseThrow ishlating.

❌ isPresent + get

if (opt.isPresent())
  x = opt.get();
Bu eski null tekshiruvidan farq qilmaydi. map/ifPresent bilan zanjirlang.

❌ maydon / parametr sifatida

Optional<String> ism; // maydon
void f(Optional<X> x)  // parametr
Serializable emas, og'ir, chalkash. Faqat return tipi uchun.

✓ return tipi sifatida

Optional<User> findById(Long id)
// Spring Data shunday qaytaradi
Chaqiruvchi "topilmasligi mumkin"ni ko'radi va tekshirishga majbur.
Spring'da
repository.findById(id).orElseThrow(() -> new NotFoundException(id)) — backend'dagi eng ko'p yoziladigan qator. Topilmasa 404 uchun exception (27-modul).
05

Suhbat savollari

?Optional nima va nima uchun?
Qiymat bo'lishi yoki bo'lmasligi mumkin bo'lgan konteyner. null o'rniga "yo'qlik"ni aniq, tipda ifodalaydi va chaqiruvchini bu holatni hal qilishga majburlaydi. NPE'ni kamaytiradi, kodni o'qiladigan qiladi (map/filter zanjiri).
?orElse va orElseGet farqi?
orElse(x) — x har doim hisoblanadi (quti to'la bo'lsa ham). orElseGet(() -> x) — faqat bo'sh bo'lganda hisoblanadi (lazy). Default qimmat bo'lsa (baza so'rovi, obyekt yaratish) — orElseGet.
?Optional'ni qayerda ishlatmaslik kerak?
Class maydoni, metod parametri, kolleksiya elementi sifatida — anti-pattern (og'ir, Serializable emas, chalkash). Faqat metod return tipi uchun. Kolleksiya qaytarganda bo'sh kolleksiya qaytaring, Optional<List> emas.
?map va flatMap Optional'da?
map — funksiya oddiy qiymat qaytarsa. flatMap — funksiya o'zi Optional qaytarsa (aks holda Optional<Optional<X>> bo'lib qoladi). Masalan user.flatMap(User::getManzilOptional).
