Redis nima va nega tez

Redis — xotirada (RAM) ishlaydigan kalit-qiymat ombori. Bankda u valyuta kurslarini keshlaydi, OTP kodlarni 2 daqiqa saqlaydi, API limitini sanaydi va ikki pod bitta to‘lovni ikki marta o‘tkazmasligi uchun qulf beradi. Avval "tez" so‘zi nimani anglatishini his qilamiz.

01

Tezlik poygasi

Bitta so‘rovga javob olish uchun turli manbalar qancha vaqt oladi? "Poyga"ni bosing. Chiziqlar haqiqiy nisbatda harakatlanadi (sekinlashtirilgan).

ChiziqliLogarifmik
Redis javobi — asosan tarmoq vaqti (~0.2–0.5 ms). Buyruqning o‘zi server ichida mikrosekundlarda bajariladi.

Inson o‘lchovida: agar 1 nanosekund = 1 soniya bo‘lsa… (kartani bosing)

Kartani bosing.
02

Nega tez? Bitta ipli event loop

Redis buyruqlarni bitta ipda, navbat bilan bajaradi. Qulf (lock) yo‘q, kontekst almashinuvi yo‘q — shuning uchun oddiy buyruq ~1 µs. Lekin bitta sekin buyruq hammani kuttiradi. Sinab ko‘ring.

Redis ipi1 ta yadrobo‘sh
epoll: minglab ulanish → bitta navbat
kurs:USD = 12650
otp:998901234567 = 4821
limit:u42 = 3
Bajarildi: 0Navbatda: 0Eng uzoq kutish: 0 ms
"Trafik"ni yoqing — buyruqlar navbatga tushadi va bittadan bajariladi.

Tezlik manbalari

1) Ma’lumot RAM’da. 2) Bitta ip — lock va race yo‘q. 3) I/O multiplexing (epoll/kqueue) — bitta ip minglab socket’ni kuzatadi. 4) Maxsus tuzilmalar (listpack, skiplist, intset). 5) Oddiy protokol (RESP).

Narxi

Bitta sekin buyruq (KEYS *, katta HGETALL, uzun Lua) butun serverni to‘xtatadi. Xotira — cheklangan va qimmat. Bitta instance faqat bitta CPU yadrosini buyruqlar uchun ishlatadi.

💡 io-threads
Redis 6+ da tarmoqdan o‘qish/yozish uchun qo‘shimcha I/O iplar bor (io-threads), Redis 8 ularni ancha kuchaytirdi. Lekin buyruqlarni bajarish baribir bitta ipda — atomiklik kafolati shundan keladi.

06

Suhbat savollari

?Redis nega bunchalik tez?›
Ma’lumot RAM’da; buyruqlar bitta ipda bajariladi — lock, kontekst almashinuvi yo‘q; I/O multiplexing (epoll) bilan bitta ip minglab ulanishga xizmat qiladi; ichki tuzilmalar ixcham va samarali (listpack, skiplist, intset); protokol oddiy. Real kechikishning katta qismi — tarmoq RTT.
?Redis bitta ipli bo‘lsa, ko‘p yadroli serverdan qanday foydalanadi?›
Buyruqlarni bajarish bitta ipda, lekin fon ishlar (fork orqali RDB, AOF fsync, UNLINK bilan asinxron o‘chirish) boshqa ip/jarayonlarda. Tarmoq I/O uchun io-threads bor. Gorizontal kengayish uchun — Redis Cluster (bir nechta shard) yoki bitta mashinada bir nechta instance.
?KEYS * nega production’da taqiqlanadi?›
U barcha kalitlarni bitta buyruqda aylanib chiqadi — O(N). 5 mln kalitda sekundlab ishlaydi va bitta ip band bo‘lgani uchun boshqa barcha mijozlar kutadi (timeout, kaskad xatolar). O‘rniga SCAN kursor bilan kichik bo‘laklarda ishlatiladi. Ko‘pincha rename-command KEYS "" yoki ACL bilan o‘chiriladi.
?Redis’ni asosiy baza sifatida ishlatsa bo‘ladimi?›
Mumkin (AOF everysec + replika), lekin cheklovlari bor: ma’lumot RAM hajmi bilan cheklangan, failover paytida asinxron replikatsiya tufayli oxirgi yozuvlar yo‘qolishi mumkin, murakkab so‘rov va tranzaksion kafolatlar zaif. Bankda pul bilan bog‘liq ma’lumot uchun — yo‘q, PostgreSQL.
?Redis va Memcached farqi?›
Memcached — faqat string, ko‘p ipli, persistence va replikatsiya yo‘q. Redis — boy tuzilmalar (hash, list, zset, stream), TTL, Lua/Functions, pub/sub, persistence, replikatsiya, cluster. Oddiy katta kesh uchun Memcached ham yetadi, lekin amalda Redis standart.
?Valkey nima?›
2024-yilda Redis litsenziyasi o‘zgargach, Linux Foundation tomonidan Redis 7.2.4 asosida yaratilgan ochiq (BSD) fork. Protokol va buyruqlar mos, ko‘plab bulut provayderlari (AWS ElastiCache, Google Memorystore) uni taklif qiladi.
