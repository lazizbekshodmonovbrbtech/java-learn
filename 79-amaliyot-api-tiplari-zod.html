Amaliyot: API tiplari, zod, xatolar

Frontend va backend o‘rtasidagi chegara — xatolarning eng ko‘p manbai: backend DTO’ni o‘zgartirdi, frontend bilmadi; API "150000" ni satr qilib qaytardi; 422 xato matni ekranda [object Object] bo‘ldi. Bu modulda chegarani uch qatlam bilan mustahkamlaymiz: tiplarni generatsiya qilish, runtime validatsiya va xatolarni tiplash.

01

02
zod: runtime’da tekshirish
Tiplar runtime’da yo‘q — lekin zod sxemasi bor: undan ham tip chiqariladi, ham qiymat tekshiriladi. Quyida kichik zod-simon validator ishlayapti: JSON’ni o‘zgartiring yoki misolni tanlang.

    

      
tolov.schema.ts
import { z } from "zod";

export const TolovSchema = z.object({
  id: z.string().regex(/^\d{6,}$/, "Faqat raqamlar"),
  summa: z.number().int().positive(),
  valyuta: z.enum(["UZS", "USD", "EUR"]),
  sana: z.string().datetime(),
  qabulQiluvchi: z.object({ ism: z.string().min(2) }).nullable(),
});
export type Tolov = z.infer<typeof TolovSchema>;     // tip sxemadan — bitta manba

const natija = TolovSchema.safeParse(await res.json());
if (!natija.success) throw new ApiShapeError(natija.error.issues);
natija.data.summa;                                     // number — endi haqiqatan

try/catchda e — unknown. Tarmoq xatosi, 401, 422 validatsiya, 500 — hammasi aralash. Discriminated union bilan har turini aniq qayta ishlash mumkin, kompilyator esa unutilganini ko‘rsatadi.

💡 Spring bilan kelishuv
Backend barcha xatolarni ProblemDetail (RFC 9457) formatida qaytarsin: type, title, status, detail + validatsiya uchun errors: [{ field, message }]. Frontend bitta toApiError() funksiyasi bilan uni Result’ga aylantiradi va formadagi maydonlarga xatolarni tarqatadi.

  


  

    
04
Suhbat savollari
?Frontend va backend tiplarini qanday sinxron tutasiz?›
Yagona haqiqat manbai — OpenAPI spetsifikatsiyasi (springdoc). Undan openapi-typescript yoki orval bilan TS tiplar/klient generatsiya qilinadi, CI’da tekshiriladi. Qo‘lda yozilgan DTO’lar tez eskiradi.
?Nega TS tiplari bo‘lsa ham zod kerak?›
TS tiplari runtime’da yo‘q; tashqi ma’lumot (API, localStorage, URL query, postMessage) tipga mos kelishiga kafolat yo‘q. zod qiymatni runtime’da tekshiradi va tipni sxemadan chiqaradi — ikki manba o‘rniga bitta. Muhim chegaralarda (pul, auth) ayniqsa.
?Java’dagi Long, BigDecimal, LocalDate TS’da qanday ifodalanadi?›
JSON’da: Long → number (2⁵³ dan katta bo‘lsa string!), BigDecimal → number yoki string (pul uchun string/butun tiyin afzal), LocalDate/Instant → ISO string (Date emas — parse o‘zingiz), enum → literal union, nullable → T | null.
?API xatolarini qanday tiplash kerak?›
Discriminated union: { tur: "network" } | { tur: "auth" } | { tur: "validation"; maydonlar } | { tur: "server"; problem }. Barcha fetch’lar bitta wrapper orqali Result qaytaradi yoki tiplangan xato otadi; UI switch bilan har holatni ko‘rsatadi, never — unutilganini ushlaydi.
?catch (e) da e ning tipi?›
useUnknownInCatchVariables (strict) bilan unknown. Ishlatishdan oldin toraytirish: e instanceof Error, maxsus type guard yoki zod.
