JOIN ichkaridan: uchta algoritm

SQL’da siz faqat JOIN … ON yozasiz. Baza esa uni uch xil usulda bajarishi mumkin — va to‘g‘ri tanlov 10 ms bilan 600 ms orasidagi farq. Har birini Java’da yozib, qadamlab ko‘ramiz; keyin haqiqiy PostgreSQL bir xil so‘rovda uchalasini qanday bajarishini solishtiramiz.

01

Nested Loop: ichma-ich sikl

Eng oddiy: har tashqi qator uchun ichki ro‘yxatni boshidan oxirigacha aylanib chiqish. Hisoblagichga qarang. Kirishni o‘zgartirib ko‘ring: hisob id’lari | tranzaksiyalarning hisob_id’si.

Kirish:
NestedLoop.java
  1. List<Juft> nestedLoop(List<Hisob> H, List<Tx> T) {
  2. List<Juft> res = new ArrayList<>();
  3. for (Hisob h : H) { // tashqi
  4. for (Tx t : T) { // ichki — har h uchun TO‘LIQ
  5. if (t.hisobId == h.id) // ON sharti
  6. res.add(new Juft(h, t));
  7. }
  8. }
  9. return res;
  10. }
02

Hash Join: avval HashMap, keyin qidirish

Ikki bosqich: kichik tomondan HashMap quriladi (BUILD), katta tomonning har qatori uchun O(1) qidiruv (PROBE). Xuddi 97-darsdagi “ikki son yig‘indisi”.

Kirish:
HashJoin.java
  1. List<Juft> hashJoin(List<Hisob> H, List<Tx> T) {
  2. Map<Long, Hisob> map = new HashMap<>(); // 1) BUILD
  3. for (Hisob h : H)
  4. map.put(h.id, h);
  5. List<Juft> res = new ArrayList<>();
  6. for (Tx t : T) { // 2) PROBE
  7. Hisob h = map.get(t.hisobId); // O(1)
  8. if (h != null)
  9. res.add(new Juft(h, t));
  10. }
  11. return res;
  12. }
03

Merge Join: fermuar

Ikkala ro‘yxat ham kalit bo‘yicha tartiblangan bo‘lsa — ikkita ko‘rsatkich bilan bir marta yurish (91-darsdagi two pointers). Tartiblash kerak bo‘lsa — avval O(n log n) saralash.

Kirish:
MergeJoin.java
  1. // H va T ikkalasi ham id bo‘yicha TARTIBLANGAN
  2. List<Juft> mergeJoin(List<Hisob> H, List<Tx> T) {
  3. List<Juft> res = new ArrayList<>();
  4. int i = 0, j = 0;
  5. while (i < H.size() && j < T.size()) {
  6. long a = H.get(i).id, b = T.get(j).hisobId;
  7. if (a < b) i++; // chap orqada — oldinga
  8. else if (a > b) j++; // o‘ng orqada — oldinga
  9. else { res.add(new Juft(H.get(i), T.get(j))); j++; }
  10. }
  11. return res;
  12. }
Nested Loop
O(N × M) · indeks bilan O(N × log M)
Tashqi tomon kichik va ichki tomonda indeks bor bo‘lsa — eng tez. Birinchi qatorlarni darhol beradi (LIMIT bilan ajoyib). Xotira kerak emas. Har qanday shart (<, >, LIKE) bilan ishlaydi.
Hash Join
O(N + M) · xotira: kichik tomon
Ikkala tomon katta, indeks yo‘q yoki foydasiz bo‘lsa. Faqat tenglik (=) sharti. Kichik tomon work_mem’ga sig‘masa — batch’larga bo‘linib diskka chiqadi.
Merge Join
O(N + M) + saralash
Ikkala tomon allaqachon tartiblangan (indeks yoki oldingi ORDER BY) bo‘lsa. Juda katta jadvallar, natija ham tartibli kerak bo‘lganda.

Planer qachon xato qiladi

Klassik falokat: planer tashqi tomonni “10 qator” deb o‘ylaydi → Nested Loop tanlaydi; aslida 100 000 qator → 100 000 ta loop. EXPLAIN’da belgisi: rows=10 (taxmin) va rows=100000 (haqiqat) Nested Loop ostida. Sabab va yechim — 119-darsda. Tez diagnostika uchun (faqat sessiyada, production kodida emas!):

diagnostika.sql
SET enable_nestloop = off;       -- Hash/Merge bilan tezlashdimi? → taxmin muammosi
EXPLAIN (ANALYZE, BUFFERS) ...;
RESET enable_nestloop;
-- Doimiy yechim: ANALYZE, CREATE STATISTICS, indeks, so‘rovni qayta yozish — enable_* EMAS
07

Suhbat savollari

?PostgreSQL qanday JOIN algoritmlarini ishlatadi?›
Nested Loop (ichki tomonda indeks bilan — Index Nested Loop), Hash Join (kichik tomondan xesh-jadval, katta tomon bilan probe), Merge Join (ikkala tomon kalit bo‘yicha tartiblangan). Planer cost’ga qarab tanlaydi.
?Qachon Nested Loop eng yaxshi?›
Tashqi tomon kichik (o‘nlab-yuzlab qator) va ichki tomonda join kaliti bo‘yicha indeks bor; LIMIT bilan birinchi qatorlar tez kerak; tenglik bo‘lmagan shartlar (BETWEEN, <) bilan.
?Hash Join qanday ishlaydi va cheklovlari?›
Build: kichik (inner) tomondan xesh-jadval work_mem’da. Probe: outer tomonning har qatori uchun xesh bo‘yicha qidiruv. O(N+M). Faqat tenglik sharti. Xesh-jadval sig‘masa — batch’larga bo‘linadi (disk). Birinchi qator build tugaguncha chiqmaydi.
?Merge Join qachon tanlanadi?›
Ikkala kirish ham join kaliti bo‘yicha tartiblangan bo‘lsa (indeks, oldingi saralash) yoki natija shu tartibda kerak bo‘lsa. Saralash kerak bo‘lsa — narxi oshadi. Juda katta, tartiblangan ma’lumotlar uchun, xotira kam ishlatadi.
?Nested Loop sekinligining belgisi rejada?›
Ichki tugunda loops juda katta (10⁵+), tashqi tugunda taxmin va haqiqat keskin farq qiladi (rows=1 vs rows=50000). Sabab ko‘pincha noto‘g‘ri taxmin — statistika.
?enable_nestloop = off ni production’da ishlatish mumkinmi?›
Global — yo‘q: boshqa so‘rovlarni buzadi. Diagnostika uchun sessiyada. Doimiy yechim — statistikani tuzatish (ANALYZE, CREATE STATISTICS), indeks, so‘rovni qayta yozish; o‘ta holatda pg_hint_plan kengaytmasi.
