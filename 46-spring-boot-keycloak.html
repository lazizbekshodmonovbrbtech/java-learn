04
SecurityConfig va rol converter'i

    
SecurityConfig.java


@Configuration @EnableMethodSecurity
class SecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(a -> a
                .requestMatchers("/actuator/health/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .oauth2ResourceServer(o -> o.jwt(j -> j.jwtAuthenticationConverter(keycloakConverter())))
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .csrf(c -> c.disable())                       // cookie yo'q, faqat Bearer
            .build();
    }

    // realm_access.roles → ROLE_*,  resource_access.hisob-service.roles → as-is,  scope → SCOPE_*
    @Bean
    JwtAuthenticationConverter keycloakConverter() {
        var scopes = new JwtGrantedAuthoritiesConverter();
        var conv = new JwtAuthenticationConverter();
        conv.setJwtGrantedAuthoritiesConverter(jwt -> {
            Collection<GrantedAuthority> out = new ArrayList<>(scopes.convert(jwt));
            Map<String, Object> realm = jwt.getClaimAsMap("realm_access");
            if (realm != null && realm.get("roles") instanceof Collection<?> roles)
                roles.forEach(r -> out.add(new SimpleGrantedAuthority("ROLE_" + r)));
            Map<String, Object> res = jwt.getClaimAsMap("resource_access");
            if (res != null && res.get("hisob-service") instanceof Map<?, ?> me
                    && me.get("roles") instanceof Collection<?> roles)
                roles.forEach(r -> out.add(new SimpleGrantedAuthority(r.toString())));
            return out;
        });
        conv.setPrincipalClaimName("preferred_username");   // authentication.getName() — log uchun qulay
        return conv;
    }
}

    
💡 Converter'siz qisqa yo'l
Keycloak'da realm rollari uchun mapper'ni tekis roles claim'iga yozadigan qilib sozlasangiz (User Realm Role mapper, Token Claim Name: roles), Spring Boot 3.2+ da faqat properties yetadi: …jwt.authorities-claim-name: roles va …jwt.authority-prefix: ROLE_. Lekin bitta claim'dan boshqasini o'qib bo'lmaydi, shuning uchun client rollari ham kerak bo'lsa, converter baribir yoziladi.

// Spring Security 6.4+: RestClient interceptor — token oladi, keshlaydi, muddati tugasa yangilaydi
@Bean
RestClient tolovClient(RestClient.Builder b, OAuth2AuthorizedClientManager manager) {
    var oauth = new OAuth2ClientHttpRequestInterceptor(manager);
    oauth.setClientRegistrationIdResolver(req -> "itr");
    return b.baseUrl("https://tolov.bank.uz").requestInterceptor(oauth).build();
}

10
Suhbat savollari

    

      
?Spring resource server Keycloak tokenini qanday tekshiradi?›
BearerTokenAuthenticationFilter header'dan tokenni oladi → JwtDecoder (Nimbus) discovery orqali topilgan JWKS'dan kalit oladi (keshlangan), imzo, exp/nbf va iss'ni tekshiradi (+ sozlangan bo'lsa aud) → JwtAuthenticationConverter claim'larni authority'larga aylantiradi → JwtAuthenticationToken SecurityContext'ga qo'yiladi → URL qoidalari va @PreAuthorize tekshiriladi. Stateless: sessiya yo'q.

      
?Nega hasRole('KASSIR') ishlamayapti, token ichida KASSIR bor?›
Default converter faqat scope/scp claim'ini o'qiydi va SCOPE_ prefiksini qo'shadi. Keycloak rollari realm_access.roles ichida — ularni o'z converter'ingiz bilan ROLE_ prefiksi qo'shib authority'ga aylantirasiz. hasRole('X') aslida hasAuthority('ROLE_X').

      
?issuer-uri va jwk-set-uri farqi?›
issuer-uri: discovery orqali JWKS'ni topadi va iss'ni avtomatik tekshiradi (Spring Boot uni birinchi so'rovgacha kechiktiradi). jwk-set-uri: faqat kalitlar manzili, iss tekshiruvi yo'q (alohida validator kerak). Docker'da ichki manzil (keycloak:8080) va tashqi issuer (auth.bank.uz) farq qilsa — jwk-set-uri'ni ichki manzilga, issuer tekshiruvini tashqi qiymatga sozlaysiz.

      
?Keycloak ishlamay qolsa API'lar nima bo'ladi?›
Mavjud tokenlar tekshirilaveradi — JWKS keshda, imzo lokal tekshiriladi. Yangi login va refresh ishlamaydi, shuning uchun 5–10 daqiqada foydalanuvchilar "chiqib ketadi". Shu sababli Keycloak HA (klaster) bo'lishi shart (48-modul). Servislar client_credentials tokenini ham yangilay olmaydi.

      
?Mikroservislar orasida foydalanuvchi kontekstini qanday uzatasiz?›
1) Token relay — kelgan Bearer tokenni keyingi servisga uzatish (aud ikkala servisni ham o'z ichiga olishi kerak). 2) Token exchange — Keycloak'dan keyingi servis uchun tor audience'li yangi token olish (xavfsizroq). 3) Servis o'z client_credentials tokeni bilan chaqiradi va foydalanuvchi ID'sini parametr qilib yuboradi — bunda chaqirilayotgan servis chaqiruvchiga ishonadi.
