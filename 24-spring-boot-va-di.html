Spring Boot: IoC va DI

Spring — obyektlarni siz o'rniga yaratadigan va bog'laydigan konteyner. Buni tushunsangiz, Spring'ning qolgan hammasi (JPA, Security, Web) shu bitta g'oyaning davomi ekanini ko'rasiz.

01

Spring Boot nima? Spring'dan farqi

Spring Framework (2003) — DI konteyner + modullar (Web MVC, Data, Security…). Sozlash ko'p edi (XML, server o'rnatish). Spring Boot (2014) — Spring'ning ustidagi qatlam: "aqlli standartlar" bilan sozlashni o'zi qiladi.

Auto-konfiguratsiya

Classpath'da PostgreSQL drayveri bor → DataSource bean'ini o'zi yaratadi. Jackson bor → JSON konvertor. Siz faqat application.yml'da URL berasiz. Mexanizm: @ConditionalOnClass, @ConditionalOnMissingBean.

Starter'lar

spring-boot-starter-web = Spring MVC + Tomcat + Jackson + Validation. Bitta dependency — mos versiyalar to'plami. starter-data-jpa, starter-security, starter-test.

Ichki server

Tomcat jar ichida. java -jar app.jar — tayyor. WAR, alohida server o'rnatish kerak emas. Docker konteyner uchun ideal.

Actuator

/actuator/health, /metrics, /info — kuzatuv endpointlari. Kubernetes liveness/readiness shu yerdan.
BankApplication.java
@SpringBootApplication   // = @Configuration + @EnableAutoConfiguration + @ComponentScan
public class BankApplication {
    public static void main(String[] args) {
        SpringApplication.run(BankApplication.class, args);   // konteyner ishga tushadi
    }
}
// @ComponentScan — shu paket va ostidagilarni skanerlaydi. Klass boshqa paketda bo'lsa — topilmaydi!

Scope: bitta nusxa yoki har safar yangi?

Default — singleton: konteynerda bitta obyekt, hamma so'rov shuni ishlatadi. Shuning uchun bean'da holat (state) saqlamang — 22-moduldagi race condition shu yerda paydo bo'ladi. getBean() ni bir necha marta chaqiring:

singleton — har getBean() bir xil obyekt (bir xil hash). Controller, Service, Repository — hammasi singleton. Thread-safe bo'lishi shart: maydonlarda foydalanuvchi ma'lumotini saqlamang.

07

Suhbat savollari

?IoC va DI farqi?
IoC — printsip: obyektlarning yaratilishi va hayotini siz emas, konteyner boshqaradi ('Hollywood printsipi: bizga qo'ng'iroq qilmang, biz qilamiz'). DI — IoC'ni amalga oshirish usuli: bog'liqliklar konstruktor/setter/maydon orqali tashqaridan beriladi. IoC — g'oya, DI — mexanizm. Spring konteyneri (ApplicationContext) — IoC konteyner.
?Bean nima? Bean hayot sikli?
Konteyner yaratadigan, sozlaydigan va boshqaradigan obyekt. Sikl: BeanDefinition o'qish → instantiate (konstruktor) → populate (inject) → Aware interfeyslar (BeanNameAware…) → BeanPostProcessor.before → @PostConstruct / InitializingBean.afterPropertiesSet → BeanPostProcessor.after (bu yerda AOP proxy yaratiladi!) → tayyor → @PreDestroy / DisposableBean.destroy.
?Constructor injection nega tavsiya qilinadi?
Maydonlar final (immutable, thread-safe), bog'liqliklar majburiy va ochiq (klass 'nimaga muhtoj'ligi imzoda), Spring'siz test (new bilan), siklik bog'liqlik startup'da xato beradi (field'da yashirin qoladi), ko'p parametr — dizayn hidi ko'rinadi. Field injection: reflection, final emas, testda mock berish qiyin.
?@Component, @Service, @Repository, @Controller farqi?
Hammasi @Component'ning ixtisoslashgan variantlari. @Repository — PersistenceExceptionTranslationPostProcessor orqali baza exception'larini Spring'ning DataAccessException ierarxiyasiga tarjima qiladi. @Controller/@RestController — MVC handler sifatida ro'yxatga oladi (@RestController = + @ResponseBody). @Service — hozircha faqat semantik (kelajakda AOP pointcut uchun qulay).
?Singleton bean'lar thread-safe'mi?
Yo'q, Spring buni kafolatlamaydi — bitta obyektni barcha so'rovlar/thread'lar bo'lishadi. Bean stateless bo'lishi kerak: maydonlarda faqat boshqa bean'lar/konfiguratsiya, so'rovga oid ma'lumot emas. Holat kerak bo'lsa — lokal o'zgaruvchi, request scope, yoki thread-safe strukturalar.
?Circular dependency qanday hal qilinadi?
Eng to'g'risi — refaktoring: umumiy mantiqni uchinchi bean'ga chiqarish yoki event (ApplicationEventPublisher) bilan bog'lanishni uzish. Vaqtinchalik: @Lazy parametrga (proxy beriladi, birinchi chaqiruvda real bean olinadi), setter injection. Boot 2.6+ spring.main.allow-circular-references=true — tavsiya qilinmaydi.
?@Autowired qanday ishlaydi? Bir nechta nomzod bo'lsa?
Tip bo'yicha qidiradi (byType). Bitta — inject. Bir nechta — parametr nomi bilan bean nomini solishtiradi; topilmasa @Primary; keyin @Qualifier; aks holda NoUniqueBeanDefinitionException. Collection/Map so'rasangiz hammasini beradi (strategiya pattern uchun qulay). required=false yoki Optional / ObjectProvider — ixtiyoriy.
?@Configuration va @Component'da @Bean farqi?
@Configuration klassi CGLIB proxy bilan o'raladi: ichida bir @Bean metod boshqasini chaqirsa, konteynerdagi singleton qaytadi (yangi obyekt emas). @Component ichidagi @Bean ('lite mode') — oddiy metod chaqiruvi, har safar yangi obyekt. Shuning uchun konfiguratsiya uchun @Configuration.
?Auto-configuration qanday ishlaydi?
@EnableAutoConfiguration → META-INF/spring/…AutoConfiguration.imports faylidagi konfiguratsiya klasslari yuklanadi, har biri @Conditional shartlar bilan: @ConditionalOnClass (classpath'da klass bor), @ConditionalOnMissingBean (siz o'zingiz bean bermagan bo'lsangiz), @ConditionalOnProperty. Sizning bean'ingiz doim ustun. --debug flag 'CONDITIONS EVALUATION REPORT' ko'rsatadi.
?ApplicationContext va BeanFactory?
BeanFactory — minimal konteyner (lazy, getBean). ApplicationContext — uning kengaytmasi: eager singleton yaratish, event publish, i18n (MessageSource), resource loading, AOP integratsiyasi, muhit (Environment). Amalda doim ApplicationContext.
