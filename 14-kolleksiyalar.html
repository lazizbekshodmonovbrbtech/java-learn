ArrayList ichida — u qanday kengayadi

ArrayList ichida oddiy massiv bor. Massiv to'lganda ArrayList yangi, kattaroq massiv yaratib, hammasini ko'chiradi (1.5 baravar). Element qo'shing va kengayish paytini kuzating — bu nega "amortized O(1)" ekanini tushuntiradi.

"ArrayList add() nima uchun O(1)?" — Ko'p hollarda shunchaki massivga yozadi (O(1)). Ba'zan to'lganda ko'chiradi (O(n)), lekin bu kamdan-kam bo'lgani uchun o'rtacha (amortized) O(1). Oldindan o'lcham bilsangiz — new ArrayList<>(1000) bilan ko'chirishlarni oldini olasiz.

06

Klassik tuzoq: ConcurrentModificationException

for-each bilan aylanayotganda kolleksiyani o'zgartirsangiz (remove) — dastur qulaydi. Bu boshlovchilarning eng ko'p uchraydigan xatosi.

CME.java
// ❌ Xato — aylanayotganda o'chirish
for (String s : list) {
    if (s.isEmpty()) list.remove(s);  // ConcurrentModificationException!
}

// ✓ To'g'ri — removeIf yoki Iterator
list.removeIf(String::isEmpty);

// ✓ yoki Iterator orqali
Iterator<String> it = list.iterator();
while (it.hasNext()) { if (it.next().isEmpty()) it.remove(); }
07

HashMap ichkaridan: put() qadamma-qadam

Kalitlar ro‘yxatini kiriting (vergul bilan). Har put(kalit, tartib_raqami) uchun: hashCode → indeks → savat (bucket) → zanjir. 13-kalitda resize: 16 savat yetmaydi (12 = 16 × 0.75), jadval 32 ga kattalashadi va hamma kalit qayta joylanadi.

Kirish:
HashMap.java (soddalashtirilgan)
  1. public V put(K key, V value) {
  2. int h = key.hashCode();
  3. h = h ^ (h >>> 16); // yuqori bitlarni aralashtirish
  4. int i = h & (table.length - 1); // = h % 16, lekin tezroq
  5. for (Node n = table[i]; n != null; n = n.next)
  6. if (n.key.equals(key)) { // shu kalit bormi?
  7. V old = n.value; n.value = value; return old; }
  8. table[i] = new Node(key, value, table[i]); // yangi tugun
  9. if (++size > threshold) // threshold = sig‘im × 0.75
  10. resize(); // 16 → 32, hammasi qayta joylanadi
  11. return null;
  12. }
Nima uchun bu muhim
get(key) ham xuddi shu yo‘ldan yuradi: hash → indeks → zanjirda equals. Zanjir qisqa bo‘lsa O(1). Shuning uchun: 1) hashCode va equals mos bo‘lishi shart (12-dars); 2) kalit o‘zgarmas bo‘lsin (String, record) — kalit o‘zgarsa, u boshqa savatda qidiriladi va “yo‘qoladi”; 3) hajm oldindan ma’lum bo‘lsa — new HashMap<>(2000), resize’lar bo‘lmaydi. Java 8+: bitta savatda 8 tadan ko‘p tugun bo‘lsa, zanjir qizil-qora daraxtga aylanadi (treeify) — eng yomon holat O(log n). “Aa” va “BB” ning hashCode’i bir xil — “To‘qnashuv” misolini sinang.
08

ConcurrentModificationException: nega yiqiladi?

for-each ichida list.remove(). Iterator ro‘yxat “o‘zgarmaganini” modCount hisoblagichi orqali tekshiradi (fail-fast).

Kirish:
CME.java
  1. List<String> list = new ArrayList<>(List.of(...));
  2. Iterator<String> it = list.iterator(); // for-each aslida shu
  3. while (it.hasNext()) { // cursor != size ?
  4. String s = it.next(); // modCount == expectedModCount ?
  5. if (s.isEmpty())
  6. list.remove(s); // modCount++ (iterator bilmaydi!)
  7. }
To‘g‘ri usullar
list.removeIf(String::isEmpty);                 // ✅ eng qisqa (Java 8+)

Iterator<String> it = list.iterator();          // ✅ iterator orqali o‘chirish
while (it.hasNext()) if (it.next().isEmpty()) it.remove();   // expectedModCount ham yangilanadi

List<String> toza = list.stream().filter(s -> !s.isEmpty()).toList();   // ✅ yangi ro‘yxat

10

Suhbat savollari

?ArrayList va LinkedList farqi?
ArrayList — ichida massiv: indeks orqali kirish O(1), o'rtaga qo'shish O(n) (surish kerak). LinkedList — bog'langan tugunlar: indeks orqali kirish O(n), boshiga qo'shish O(1), ko'proq xotira. Amalda deyarli doim ArrayList.
?HashMap qanday ishlaydi?
Kalitning hashCode() dan bucket indeksini hisoblaydi, o'sha bucketda equals() bilan aniq kalitni topadi. Bir bucketga ko'p tushsa (collision) — zanjir (linked list), Java 8+ da 8 tadan oshsa daraxt (red-black tree). Load factor 0.75 dan oshsa bucketlar soni 2 baravar oshadi (rehash).
?HashSet ichida nima bor?
Aslida HashMap! HashSet elementlarni HashMap'ning kaliti sifatida saqlaydi (qiymat — bo'sh obyekt). Shuning uchun takrorsiz va O(1) — HashMap kalitlari takrorlanmaydi.
?HashMap va Hashtable / ConcurrentHashMap farqi?
HashMap — thread-safe emas, tez, null kalitga ruxsat. Hashtable — eski, butunlay sinxronlangan (sekin). ConcurrentHashMap — zamonaviy thread-safe, segmentli qulflash (tez). Ko'p thread'da — ConcurrentHashMap (22-modul).
?HashMap’da load factor va resize qanday ishlaydi?›
Standart sig‘im 16, load factor 0.75 → threshold 12. size threshold’dan oshsa, jadval 2 baravar kattalashadi va har tugun yangi indeksga ko‘chiriladi (Java 8+ da tugun yoki eski joyida qoladi, yoki +eski_sig‘im ga ko‘chadi — hash’ning bitta biti bo‘yicha). Resize — O(n), shuning uchun hajm ma’lum bo‘lsa boshlang‘ich sig‘im bering.
?Treeify nima?›
Java 8+: bitta savatdagi zanjir uzunligi 8 dan oshsa (va jadval ≥ 64 bo‘lsa) zanjir qizil-qora daraxtga aylanadi — eng yomon holat O(n) dan O(log n) ga. 6 dan kamaysa qaytadan ro‘yxat.
?Fail-fast va fail-safe iteratorlar farqi?›
Fail-fast (ArrayList, HashMap) — iteratsiya paytida strukturaviy o‘zgarish bo‘lsa modCount orqali aniqlab, CME tashlaydi (kafolat emas, best-effort). Fail-safe / weakly consistent (CopyOnWriteArrayList, ConcurrentHashMap) — nusxa yoki o‘zgarishga chidamli iterator, CME tashlamaydi, lekin oxirgi o‘zgarishlarni ko‘rmasligi mumkin.
?Nega HashMap kaliti o‘zgarmas (immutable) bo‘lishi kerak?›
Kalit qo‘yilganda uning hashCode’i bo‘yicha savat tanlanadi. Keyin kalit obyekti o‘zgarsa, hashCode boshqa — get() boshqa savatda qidiradi va topa olmaydi; eski yozuv “yo‘qoladi” (memory leak). String, Integer, record — xavfsiz.
?LinkedHashMap bilan LRU kesh qanday yasaladi?›
new LinkedHashMap<>(16, 0.75f, true) — accessOrder=true: get() elementni oxiriga suradi. removeEldestEntry(…) ni override qilib, size() > MAX bo‘lsa eng eskisini o‘chirish.
?List.of() va Arrays.asList() farqi?›
List.of — to‘liq o‘zgarmas: add/set/remove → UnsupportedOperationException, null qabul qilmaydi. Arrays.asList — massivga “ko‘rinish”: set mumkin (massiv ham o‘zgaradi), add/remove — yo‘q.
