03

Vaziyatli savollar

?Jamoada hamma joyda "as any" ishlatilyapti. Nima qilasiz?›
Sababini topish: odatda noto‘g‘ri yoki yo‘q tiplar (kutubxona, API). Tiplarni generatsiya qilish (OpenAPI), unknown + toraytirish/zod, kerakli joyda to‘g‘ri generic. ESLint: no-explicit-any (warn → error), no-unsafe-* qoidalar; yangi kodda taqiq, eskisini bosqichma-bosqich.
?Backend javobi TS tipiga mos emasligi production’da ma’lum bo‘ldi. Qanday oldini olasiz?›
Kontrakt: OpenAPI’dan tiplar generatsiyasi CI’da (spec o‘zgarsa build yiqiladi), muhim endpoint’larda zod bilan runtime validatsiya va monitoring (validatsiya xatolarini log/alert), consumer-driven contract testlar (Pact yoki Spring Cloud Contract).
?Katta JS loyihani TS’ga o‘tkazish rejasi?›
allowJs, checkJs yoki JSDoc; tsconfig avval yumshoq; eng ko‘p ishlatiladigan umumiy modullar va API qatlamidan boshlash; yangi fayllar faqat .ts; strict flag’larni birma-bir yoqish; CI’da tsc --noEmit.
?Pul summasini TS’da qanday tiplaysiz?›
Float xavfi sababli: tiyinlarda butun son (number, Number.isSafeInteger bilan) yoki string (decimal kutubxonasi bilan), branded tip (type Tiyin = Brand) — boshqa sonlar bilan aralashmasin. Ko‘rsatish — Intl.NumberFormat.
?enum’dan foydalanishni tavsiya qilasizmi?›
Ko‘p hollarda union literal yoki as const obyekt afzal: runtime kodi yo‘q, JSON bilan mos, raqamli enum’ning xavfli tomoni yo‘q. enum faqat jamoa standarti bo‘lsa.
