Tiplar va operatorlar

Har dastur ma'lumot bilan ishlaydi. Java'da har qiymatning qat'iy tipi bor — va bu tipning ichida nozik tuzoqlar yashiringan: son toshib ketishi, kasr xatolari, Integer keshi. Suhbatda aynan shular so'raladi.

01

Sakkiz primitiv tip

Java'da tiplar ikki oilaga bo'linadi: primitiv (8 ta, qiymatni o'zida saqlaydi) va reference (obyektlar, manzil saqlaydi). Bir tipni bosing — o'lchami, diapazoni va qachon ishlatilishini ko'ring.

primitiv reference
amalda
Kundalik ishda asosan int, long, double, boolean, char ishlatiladi. byte va short — kamdan-kam (xotira juda muhim bo'lganda). Katta ID va vaqt uchun long.
02

Primitiv qiymatni to'g'ridan-to'g'ri Stack'da saqlaydi. Reference esa qiymatni emas, Heap'dagi obyektning manzilini saqlaydi. Bu farq keyinchalik == va equals, hamda pass-by-value mavzularida hal qiluvchi bo'ladi. O'zgaruvchini bosing.

03

Son toshib ketishi (overflow)

int maksimal qiymati — 2,147,483,647. Unga 1 qo'shsangiz nima bo'ladi? Xato emas — son eng kichik manfiy songa "aylanib" tushadi. Bu jimgina yuz beradi va bank tizimlarida jiddiy xatolarga sabab bo'ladi. Slayderni maksimalgacha suring.

2000000000
int qiymati
int hali xavfsiz diapazonda. MAX (2,147,483,647) dan oshirib ko'ring.
bank ishida muhim
Pul yoki katta hisoblarni int'da saqlamang — toshib ketadi. long ishlating (yoki tiyin/sent uchun ham long). Aniq kasrli pul uchun esa — BigDecimal (keyingi bo'limda).
04

Kasr sonlar yolg'on gapiradi

Bu har bir dasturchini bir marta shoshiradi. double va float — ikkilik (binary) sanoq sistemasida saqlanadi, va o'nlik kasrlarni aniq ifodalay olmaydi. Natijada:

Kasr.java
System.out.println(0.1 + 0.2);
// kutilgan: 0.3
// haqiqiy:  0.30000000000000004  😱

// Pul uchun to'g'ri yechim — BigDecimal:
BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
System.out.println(a.add(b));  // aniq 0.3 ✓
suhbatda
"Pulni double'da saqlash mumkinmi?" — Yo'q. double aniq emas, tiyinlar yo'qoladi. Pul uchun BigDecimal (String'dan yaratilgan) yoki butun sonli tiyin/sent (long). Bu bank orqasidagi dasturchi uchun asosiy savol.

Operatorlar.java

      
// ++ oldin va keyin:
int a = 5;
int b = a++;  // b=5 (avval berdi, keyin oshdi), a=6
int c = ++a;  // a=7, c=7 (avval oshdi, keyin berdi)

// ternary — qisqa if/else:
String holat = (yosh >= 18) ? "katta" : "kichik";

// qisqa tutashuv — chap yolg'on bo'lsa, o'ng tekshirilmaydi:
if (obj != null && obj.faol()) { ... }  // xavfsiz

    

    

      
qisqa tutashuv nega muhim

      obj != null && obj.faol() — agar obj null bo'lsa, && o'ng tomonni umuman tekshirmaydi, shuning uchun NullPointerException bo'lmaydi. Bu himoyaning eng ko'p ishlatiladigan usuli.
    

  


  

    
07
Tiplar orasida o'tish (casting)

    
Kichikdan kattaga — avtomatik (xavfsiz). Kattadan kichikga — qo'lda va ma'lumot yo'qolishi mumkin.

    

      
Casting.java

      
int n = 25;
double d = n;         // avtomatik: int → double, xavfsiz

double pi = 3.99;
int butun = (int) pi;  // qo'lda: kasr KESILADI → 3 (yaxlitlamaydi!)

long katta = 10000000000L;  // L qo'shimchasi shart (int'ga sig'maydi)

    

    

      
diqqat

      (int) 3.99 = 3, 4 emas. Casting yaxlitlamaydi — kasr qismini shunchaki kesib tashlaydi. Yaxlitlash uchun Math.round() ishlating.
    

  


  

    
08
var va final

    
var — tipni Java o'zi aniqlaydi (Java 10+, faqat lokal). final — bir marta qiymat berilgach o'zgarmaydigan (konstanta).

    

      
VarFinal.java

      
var son = 42;          // Java aniqlaydi → int (tip baribir bor!)
var nom = "Java";      // → String

final double PI = 3.14159;
PI = 3.2;   // ❌ kompilyatsiya xatosi: final o'zgarmaydi

    

    

      
tez-tez so'raladi

      "var — Java endi dinamik tipli bo'ldimi?" — Yo'q. Tip baribir bor va o'zgarmaydi, shunchaki yozilmaydi (compile-time'da aniqlanadi). var x = 5; keyin x = "salom"; — xato.

11
Suhbat savollari

    

      
?Primitiv va reference tip farqi?
Primitiv (int, double...) qiymatni to'g'ridan-to'g'ri Stack'da saqlaydi. Reference (String, obyektlar) Heap'dagi obyektning manzilini saqlaydi. Primitivlar tezroq, null bo'lolmaydi; reference'lar null bo'lishi mumkin.

      
?==  va equals() farqi?
== — primitivlarda qiymatni, obyektlarda manzilni (bir xil obyektmi?) solishtiradi. equals() — mazmunni solishtiradi. Obyektlar (String, Integer) uchun doim equals ishlating — Integer keshi tuzog'i aynan shundan kelib chiqadi.

      
?Pulni qaysi tipda saqlaysiz?
BigDecimal (String konstruktoridan) yoki butun sonli eng kichik birlik (tiyin/sent) uchun long. Hech qachon double/float emas — ular aniq emas, kasr xatolari pul hisobini buzadi.

      
?Integer overflow'da nima bo'ladi?
Xato ham, ogohlantirish ham bermaydi — son jimgina eng kichik manfiy songa "aylanib" tushadi (wrap-around). Katta qiymatlar uchun long yoki Math.addExact() (u overflow'da exception tashlaydi).

      
?char qanday saqlanadi?
char — 2 baytlik Unicode raqami. Aslida u son: 'A' = 65. Shuning uchun char'ni songa qo'shsa bo'ladi: 'A' + 1 = 66 = 'B'.

    
?int overflow nima va qanday oldini olasiz?›
int 32-bit (−2³¹ … 2³¹−1); chegaradan oshsa jimgina “aylanib” manfiyga o‘tadi. Oldini olish: long, Math.addExact/multiplyExact (ArithmeticException tashlaydi), pul uchun BigDecimal. Ifodada kamida bitta operand long bo‘lsin: 1_000_000L * 1_000_000.
?Integer == Integer nega 127 da true, 128 da false?›
Autoboxing Integer.valueOf ishlatadi, u −128…127 oralig‘idagi obyektlarni keshlaydi — bir xil obyekt qaytadi. 128 da yangi obyektlar — == manzillarni solishtiradi. Har doim equals() yoki primitivga o‘tkazing.
?Nega 0.1 + 0.2 != 0.3?›
double — ikkilik kasr; 0.1 ni ikkilikda aniq yozib bo‘lmaydi (cheksiz kasr). Pul hisobida BigDecimal (String konstruktori bilan: new BigDecimal("0.1")) yoki tiyinda long.
?s += 1.7 (s int) nega kompilyatsiya bo‘ladi, s = s + 1.7 esa yo‘q?›
Compound assignment yashirin cast qiladi: s = (int)(s + 1.7). Oddiy = da double → int toraytirish aniq cast talab qiladi.
?&& va & farqi?›
&& — qisqa tutashuv: chap tomon false bo‘lsa o‘ng tomon hisoblanmaydi (x != null && x.isEmpty() xavfsiz). & — har ikki tomon ham hisoblanadi (va bitwise AND).
