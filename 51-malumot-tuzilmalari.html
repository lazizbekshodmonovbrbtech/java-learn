Ma’lumot tuzilmalari

Redis — shunchaki "kalit → satr" emas. Har bir kalit ortida tayyor tuzilma turadi: hash, ro‘yxat, to‘plam, tartiblangan to‘plam. To‘g‘ri tuzilmani tanlash — Redis bilan ishlashning 80%i. Quyida haqiqiy redis-cliga o‘xshash simulyator bor: buyruq yozing yoki missiyalarni bosing va xotirada nima bo‘layotganini ko‘ring.

💡 String yoki Hash? (obyektni saqlash)
Profilni JSON string qilib saqlasangiz (SET user:42 {...}) — bitta maydonni o‘zgartirish uchun butun JSON’ni o‘qib-yozasiz, parallel yozuvlar bir-birini bosib ketadi. Hash’da (HSET user:42 status BLOCKED) har maydon alohida va atomik o‘zgaradi, HINCRBY bilan sanash ham mumkin. Lekin Redis 7.4 gacha TTL faqat butun kalitga qo‘yilardi; 7.4+ da HEXPIRE bilan maydonga ham qo‘yish mumkin.
03

Ichki kodlash (encoding): kichik — ixcham, katta — tez

Redis bir tuzilmani ikki xil saqlaydi. Kichik bo‘lsa — listpack (ketma-ket baytlar, juda tejamkor, lekin qidirish O(N)). Chegara oshsa — avtomatik hashtable/skiplistga o‘tadi (ko‘proq xotira, lekin O(1)/O(log N)). Laboratoriyada Sorted Set missiyasidagi "+200 a’zo" tugmasini bosib, listpack → skiplist o‘tishini ko‘ring.

🎯 Suhbat: Sorted Set qanday ishlaydi?
Katta ZSet ikki tuzilmadan iborat: hashtable (element → ball, ZSCORE O(1)) va skiplist (ball bo‘yicha tartib, ZADD/ZRANK/ZRANGE O(log N)). Skiplist — bir necha qavatli bog‘langan ro‘yxat: yuqori qavatlar "ekspress poyezd", pastkisi — hamma bekatlar. Balanslangan daraxtdan soddaroq, oralig‘ bo‘yicha o‘qish qulay.

06

Maxsus tuzilmalar

🟩 Bitmap

String ustida bitlar. SETBIT login:2026-09-23 42 1 — 42-foydalanuvchi bugun kirdi. 10 mln foydalanuvchi = 1.2 MB. BITCOUNT — kunlik faollar.

🔢 HyperLogLog

Taxminiy noyob sanoq: 12 KB’da milliardlab element, ~0.81% xato. PFADD visitors:app u42, PFCOUNT. Aniq son kerak bo‘lmagan statistika uchun.

📍 Geo

Sorted Set ustida koordinatalar. GEOADD atm 69.24 41.31 atm:17, GEOSEARCH atm FROMLONLAT … BYRADIUS 2 km ASC — eng yaqin bankomatlar.

{ } JSON va Streams

Redis 8’da JSON, Search, Time series modullari tarkibda. Streams — hodisalar jurnali, consumer group bilan (56-modul).

07

Java’dan ishlatish (ko‘rinishi)

Spring Data Redis’da har tuzilma uchun alohida "ops" bor. To‘liq konfiguratsiya — 56-modulda.

CardCacheService.java
@Service
@RequiredArgsConstructor
class CardCacheService {
    private final StringRedisTemplate redis;

    void block(long cardId) {
        redis.opsForHash().put("card:" + cardId, "status", "BLOCKED");      // HSET
    }
    void pushTx(long userId, String tx) {
        String key = "tx:last:" + userId;
        redis.opsForList().leftPush(key, tx);                                 // LPUSH
        redis.opsForList().trim(key, 0, 9);                                   // LTRIM 0 9
    }
    Set<String> topCashback(String month) {
        return redis.opsForZSet().reverseRange("cashback:" + month, 0, 9);  // ZREVRANGE
    }
}
08

Suhbat savollari

?Redis’dagi asosiy ma’lumot tuzilmalarini va ularning qo‘llanishini ayting.›
String (kesh, hisoblagich, lock), Hash (obyekt maydonlari), List (navbat, oxirgi N ta), Set (noyob to‘plam, kesishma), Sorted Set (reyting, vaqt bo‘yicha oyna, ustuvor navbat). Qo‘shimcha: Bitmap, HyperLogLog, Geo, Streams, JSON.
?Obyektni String (JSON) yoki Hash’da saqlashning farqi?›
Hash’da maydonlar alohida o‘qiladi/o‘zgaradi (HGET, HSET, HINCRBY) — qisman yangilash atomik, tarmoq trafik kam. JSON string’da butun obyekt o‘qib-yoziladi, ichki struktura saqlanadi, serializatsiya oddiy. Kichik hash’lar listpack’da juda ixcham. Ichma-ich murakkab obyekt bo‘lsa — JSON (yoki RedisJSON).
?Sorted Set ichki tuzilishi va murakkabligi?›
Kichik — listpack. Katta — skiplist + hashtable. ZADD/ZREM/ZRANK — O(log N), ZSCORE — O(1), ZRANGE — O(log N + M).
?List’ni navbat sifatida qanday ishlatasiz va cheklovlari?›
Producer LPUSH, consumer BRPOP (bloklovchi). Kamchiligi: element olingach, consumer yiqilsa xabar yo‘qoladi (LMOVE bilan "processing" ro‘yxatga ko‘chirish kerak), ack yo‘q, bir nechta consumer group yo‘q. Ishonchli navbat uchun — Streams yoki Kafka.
?HGETALL nega xavfli bo‘lishi mumkin?›
O(N): katta hash’da serverni bloklaydi va ko‘p trafik yaratadi. Kerakli maydonlarni HMGET bilan oling yoki HSCAN bilan bo‘laklab o‘qing.
?Kunlik noyob foydalanuvchilarni qanday sanaysiz?›
Aniq kerak bo‘lsa — Set (xotira ko‘p) yoki Bitmap (ID’lar zich butun son bo‘lsa, juda tejamkor). Taxminiy bo‘lsa — HyperLogLog (12 KB, ~0.81% xato).
