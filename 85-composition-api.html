Composition API va composable’lar

Komponent kattalashgan sari Options API’da bitta vazifa kodi (qidiruv, sahifalash, kurs yangilanishi) data, computed, methods, mounted bo‘ylab tarqalib ketadi. Composition API bir vazifani bir joyga yig‘adi va uni composable — qayta ishlatiladigan useXxx() funksiyaga chiqarishga imkon beradi. Java tilida aytsak — mantiqni service’ga ajratish.

composables/useDebounce.ts
export function useDebounce<T>(src: Ref<T>, ms = 300) {
  const out = ref(src.value) as Ref<T>
  let t: number | undefined
  watch(src, v => {
    clearTimeout(t)
    t = setTimeout(() => (out.value = v), ms)
  })
  onScopeDispose(() => clearTimeout(t))   // tozalash!
  return out
}
composables/useMijozQidiruv.ts
export function useMijozQidiruv() {
  const soz = ref('')
  const kechikkan = useDebounce(soz, 300)
  const natija = ref<Mijoz[]>([])
  const yuklanmoqda = ref(false)

  watch(kechikkan, async (q, _, onCleanup) => {
    const ctrl = new AbortController()
    onCleanup(() => ctrl.abort())      // yangi q kelsa — eskisini bekor qil
    yuklanmoqda.value = true
    try {
      natija.value = await api.get('/clients', { params: { q }, signal: ctrl.signal })
    } finally { yuklanmoqda.value = false }
  })
  return { soz, natija, yuklanmoqda }
}

04

Suhbat savollari

?Composition API nima uchun kerak, Options API’dan farqi?›
Options API kodni turi bo‘yicha (data, methods, computed) ajratadi — katta komponentda bitta vazifa kodi tarqalib ketadi. Composition API vazifa bo‘yicha guruhlaydi va mantiqni composable funksiyalarga chiqarishga imkon beradi. Qo‘shimcha: TypeScript bilan yaxshi tip chiqarish, mixin’lardagi nom to‘qnashuvi va "bu xossa qayerdan keldi?" muammosi yo‘q.
?Composable nima? Mixin’dan nima ustunligi bor?›
Holatli mantiqni o‘z ichiga olgan funksiya (useXxx), ref’lar qaytaradi. Mixin’dan farqi: qaytgan qiymatlar aniq (destructuring bilan ko‘rinadi), nom to‘qnashuvi bo‘lsa qayta nomlash oson, parametr qabul qiladi, bir necha marta turli sozlamalar bilan ishlatish mumkin.
?Qidiruvda debounce va race condition qanday hal qilinadi?›
Debounce — foydalanuvchi yozishni to‘xtatgandan keyin (300 ms) so‘rov. Race — watch’ning onCleanup’ida AbortController.abort() (yoki javob kelganda so‘rov ID’sini tekshirish), shunda eski javob yangisini ustidan yozmaydi. Server tomonda ham limit/rate limit.
?watch va watchEffect farqi?›
watch — aniq manba, lazy, eski/yangi qiymat beradi. watchEffect — darhol ishlaydi va ichida o‘qilganlarni avtomatik kuzatadi. Ikkalasi ham cleanup va flush (pre/post/sync) opsiyalariga ega.
?Composable’ni await’dan keyin chaqirsa nima bo‘ladi?›
setup’dagi joriy komponent instansiyasi await’dan keyin yo‘qoladi — composable ichidagi onMounted/onUnmounted hech kimga bog‘lanmaydi (ogohlantirish), tozalash ishlamaydi. Composable’larni setup boshida sinxron chaqiring.
