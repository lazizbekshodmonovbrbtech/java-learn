Komponentlar: props pastga, emit yuqoriga

Internet-bank sahifasi — o‘nlab komponentdan iborat daraxt. Ular qanday gaplashadi? Qoida bitta: ma’lumot pastga props bilan tushadi, hodisalar yuqoriga emit bilan chiqadi. Bola ota ma’lumotini o‘zi o‘zgartirmaydi — so‘raydi. Quyida buni paketlar harakatida, slotlarni "teshiklar" sifatida va lifecycle hook’lar tartibini qadam-baqadam ko‘ramiz.

01

One-way data flow: jonli

Karta ostidagi Bloklashni bosing: to‘q sariq paket (emit) yuqoriga chiqadi, App holatni o‘zgartiradi, ko‘k paketlar (props) pastga tushadi. Keyin "❌ props’ni to‘g‘ridan o‘zgartirish"ni sinang.

emit (hodisa ↑)props (ma’lumot ↓)
Holat (kartalar ro‘yxati) faqat App’da yashaydi — "yagona haqiqat manbai". Bolalar uni props orqali faqat o‘qiydi.
KartaItem.vue (bola)
<script setup lang="ts">
const props = defineProps<{ karta: Karta }>()
const emit = defineEmits<{
  bloklash: [id: number]
}>()
</script>

<template>
  <div>{{ karta.raqam }} — {{ karta.holat }}</div>
  <button @click="emit('bloklash', karta.id)">
    Bloklash
  </button>
</template>
App.vue (ota)
<script setup lang="ts">
const kartalar = ref<Karta[]>([...])

async function bloklash(id: number) {
  await api.post(`/cards/${id}/block`)
  const k = kartalar.value.find(k => k.id === id)
  if (k) k.holat = 'blok'   // ✅ egasi o'zgartiradi
}
</script>

<template>
  <KartaRoyxati :kartalar="kartalar"
                @bloklash="bloklash" />
</template>

Slotlar: komponentdagi "teshiklar"

Bitta BaseModal — sarlavha, tana va tugmalar joyi bo‘sh (slot). Ota komponent ularni o‘z kontenti bilan to‘ldiradi. Chapdan stsenariy tanlang.

<BaseModal>✕
<slot name="header">Standart sarlavha
<slot> (default)—
<slot name="footer">[ Yopish ] ← fallback kontent
Slot — komponent ichida ota kontenti uchun ajratilgan joy. Ota bermasa — fallback ko‘rinadi.
BaseModal.vue
<template>
  <div class="modal">
    <header><slot name="header">Standart sarlavha</slot></header>
    <main><slot /></main>
    <footer>
      <slot name="footer">
        <button @click="$emit('close')">Yopish</button>
      </slot>
    </footer>
  </div>
</template>
Ota: slotlarni to‘ldirish + scoped slot

  <template #footer>
    <button @click="tasdiqla">Tasdiqlash</button>
  </template>
</BaseModal>

  <template #row="{ item }">

    05

    Suhbat savollari

    ?Props va emit — one-way data flow nima?›
    Ma’lumot ota → bola props orqali oqadi, bola props’ni o‘zgartirmaydi (readonly, dev rejimda ogohlantirish). O‘zgartirish kerak bo‘lsa bola emit bilan hodisa yuboradi, holat egasi (ota yoki store) o‘zgartiradi. Natija — holat qayerda o‘zgarishini topish oson, debugging bashorat qilinadigan.
    ?Props obyekt bo‘lsa, bola props.karta.holat = "x" qilsa nima bo‘ladi?›
    Props proxy’si shallow readonly — props.karta = … ga ruxsat yo‘q, lekin ichki xossani mutatsiya qilish texnik jihatdan ishlaydi (obyekt ota bilan umumiy) va otaning holati jimgina o‘zgaradi. Bu anti-pattern: ma’lumot oqimi yashirin bo‘ladi. To‘g‘risi — emit yoki lokal nusxa.
    ?Slot va scoped slot farqi?›
    Oddiy slot — ota kontentni bola ichiga qo‘yadi, kontent ota scope’ida kompilyatsiya qilinadi. Scoped slot — bola slotga ma’lumot uzatadi (<slot :item="row">), ota uni #row="{ item }" orqali oladi. Jadval, ro‘yxat, renderless komponentlar uchun.
    ?Ota va bola hook’lari qaysi tartibda ishlaydi?›
    Mount: ota setup → ota onBeforeMount → bola setup → bola onBeforeMount → bola onMounted → ota onMounted (ota oxirida, chunki uning DOM’i bolalarni ham o‘z ichiga oladi). Unmount ham shunga o‘xshash: ota beforeUnmount → bola beforeUnmount → bola unmounted → ota unmounted.
    ?API chaqiruvini qaysi hook’da qilasiz?›
    setup’da (async funksiyani chaqirib, natijani ref’ga yozish) yoki onMounted’da — ikkalasi ham ishlaydi; SSR bo‘lsa onMounted server’da ishlamaydi. DOM kerak bo‘lsa — faqat onMounted. Komponent tez-tez qayta mount bo‘lsa — so‘rovni bekor qilish (AbortController) onUnmounted’da.
    ?provide/inject qachon Pinia o‘rniga?›
    Daraxtning bir qismiga tegishli kontekst (forma, tema, murakkab komponent kutubxonasi ichki holati) — provide/inject. Ilova bo‘ylab global, devtools’da kuzatiladigan holat — Pinia.
