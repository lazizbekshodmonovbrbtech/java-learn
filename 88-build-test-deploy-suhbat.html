npm run build — ichkaridan

Vite (Rollup) bosqichlari. Har qadamda fayllar va umumiy hajm qanday o‘zgarishini kuzating.

    Dockerfile — multi-stage
    # 1) build: Node faqat shu bosqichda
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build          # vue-tsc --noEmit && vite build → /app/dist

# 2) runtime: faqat statik fayllar + nginx (~25 MB image)
FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
    nginx.conf
    server {
  listen 80;
  root /usr/share/nginx/html;

  location /assets/ {                       # hash'li fayllar — abadiy kesh
    add_header Cache-Control "public, max-age=31536000, immutable";
  }
  location / {
    try_files $uri /index.html;             # SPA history mode fallback
    add_header Cache-Control "no-cache";     # index.html doim yangi
  }
  location /api/ { proxy_pass http://backend:8080; }   # CORS kerak emas
}
    Muhit sozlamalari
    import.meta.env.VITE_API_URL build paytida kodga yozib qo‘yiladi — bitta image’ni dev/prod’da ishlatish uchun runtime config (/config.json yoki nginx’da envsubst). Va eslang: VITE_ o‘zgaruvchilar brauzerda ochiq — u yerga sir (secret) qo‘yilmaydi.

    Vaziyatli savollar

    ?Sahifa ochilishi 6 soniya. Qanday tahlil qilasiz va tezlashtirasiz?›
    O‘lchash: Lighthouse, Network (bundle hajmi, so‘rovlar zanjiri), Performance. Yechimlar: route bo‘yicha lazy loading, og‘ir kutubxonalarni (grafik, xarita) dinamik import, tree-shaking’ni buzuvchi importlarni tuzatish (lodash → lodash-es yoki alohida funksiyalar), rasmlarni siqish, gzip/brotli, kesh (hash + immutable), API so‘rovlarini parallel qilish va keraksizini kechiktirish, katta ro‘yxatda virtual scroll.
    ?Deploy’dan keyin ba’zi foydalanuvchilarda oq ekran. Sababi?›
    Ko‘pincha: index.html keshlangan va u yangi deploy’da o‘chirilgan eski hash’li chunk’larni so‘raydi (404). Yechim: index.html no-cache, eski asset’larni bir muddat saqlash, router.onError’da chunk yuklash xatosida sahifani qayta yuklash.
    ?Frontend’da XSS’dan qanday himoyalanasiz?›
    {{ }} avtomatik escape qiladi; v-html’ni foydalanuvchi matni bilan ishlatmaslik (kerak bo‘lsa DOMPurify); URL’larni tekshirish (javascript: sxemasi); CSP header; token’ni localStorage’da saqlamaslik yoki BFF pattern; bog‘liqliklarni npm audit / Dependabot bilan kuzatish.
    ?Vue 2 → Vue 3 migratsiyasi rejasi?›
    @vue/compat (migration build) bilan boshlash, ogohlantirishlarni birma-bir yopish: global API (createApp), v-model o‘zgarishlari, filtrlar olib tashlangan, event bus yo‘q ($on); Vuex → Pinia; Vue Router 4; Vuetify va boshqa UI kutubxonalarining 3-versiyasi. Yangi kod — Composition API + TS, eskisi bosqichma-bosqich.
    ?Backend dasturchi sifatida frontend jamoa bilan API kontraktini qanday kelishasiz?›
    OpenAPI spetsifikatsiyasi (springdoc) — yagona manba; frontend tiplarni generatsiya qiladi (openapi-typescript/orval); o‘zgarishlar versiyalanadi; xatolar ProblemDetail formatida; sahifalash, sana (ISO) va pul formatlari (string yoki tiyin) kelishilgan; mock server (MSW) bilan parallel ishlash.
