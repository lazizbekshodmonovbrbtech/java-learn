Metodlar

Bir xil kodni qayta yozmang — uni "qadoqlab" nom bering, keyin istagancha chaqiring. Metod kirish oladi, ishlaydi, natija qaytaradi. Va Java'ning eng ko'p yanglishtiradigan mavzusi: pass-by-value.

01

Metodni qismlab

Har bo'lakning aniq vazifasi bor. Rangli qismlarni bosing.

Calculator.java
public int jami(int a, int b) {
    int natija = a + b;
    return natija;
}

// chaqirilishi:
int x = jami(2, 3);   // x = 5
02

Parametr va argument

parametr — metod ta'rifidagi bo'sh joy (int a, int b). argument — chaqirishda beradigan haqiqiy qiymat (2, 3). Parametr — quti, argument — unga solingan narsa.

03

Call stack — metodlar bir-birini chaqirganda

Metod boshqa metodni chaqirsa, JVM Stack'ga yangi "ramka" (frame) qo'yadi. Metod tugasa, ramka olib tashlanadi va natija chaqiruvchiga qaytadi. Oxirgi kirgan birinchi chiqadi. main → jami → kopaytir zanjirini kuzating.

Chain.java
void main() { int r = jami(2, 3); }
int jami(int a, int b) { return kopaytir(a + b, 2); }
int kopaytir(int x, int y) { return x * y; }
↑ oxirgi kirgan, birinchi chiqadi
StackOverflowError
Metod o'z-o'zini cheksiz chaqirsa (to'xtash sharti yo'q rekursiya), Stack to'lib ketadi — mashhur StackOverflowError. Har rekursiyada to'xtash sharti (base case) bo'lishi shart.
04

Pass-by-value — Java'ning eng chalkash mavzusi

Java doim qiymatni nusxalab uzatadi (pass-by-value). Lekin bu primitiv va obyekt uchun boshqacha ko'rinadi. Metod ichida o'zgartirsangiz, tashqaridagi o'zgaradimi? Ikkovini "yugurtiring" va farqni ko'ring — bu suhbatning eng sevimli savoli.

main() — tashqarida
metod() — ichkarida (nusxa)
HEAP — obyekt
to'liq javob
"Java pass-by-value mi, pass-by-reference mi?" — Doim pass-by-value. Primitivda qiymatning nusxasi uzatiladi. Obyektda esa manzilning (reference) nusxasi uzatiladi — shuning uchun obyekt ichini o'zgartirsa tashqarida ko'rinadi, lekin parametrni yangi obyektga qayta tayinlasa — tashqarida ko'rinmaydi.
05

Overloading, varargs, rekursiya

Overloading — bir nom, turli parametrlar. Java argumentlarga qarab qaysi birini tanlaydi.

jami(int a, int b)ikki butun son
jami(double a, double b)ikki kasrli son
jami(int... sonlar)varargs — istalgancha son
Varargs.java
// varargs — istalgancha argument qabul qiladi
int jami(int... sonlar) {   // ichida array kabi
    int s = 0;
    for (int n : sonlar) s += n;
    return s;
}
jami(1, 2, 3);       // 6
jami(5, 10, 15, 20); // 50

// rekursiya — metod o'z-o'zini chaqiradi (base case bilan!)
int factorial(int n) {
    if (n <= 1) return 1;    // base case — to'xtash
    return n * factorial(n - 1);
}

static metod

Obyektsiz, class orqali chaqiriladi. Yordamchi funksiyalar.

Math.max(3, 7);

instance metod

Avval obyekt yaratasiz, keyin uning ustidan chaqirasiz.

ism.length();
06

Rekursiya: stek qanday o‘sadi va qisqaradi

Har chaqiruv stekka yangi kadr (frame) qo‘yadi — o‘z ni bilan. Asosiy holatga yetgach, javoblar teskari tartibda “qaytadi”. n ni o‘zgartiring; base case’siz variantni ham sinang.

Kirish:
Faktorial.java
  1. static long faktorial(int n) {
  2. if (n <= 1) // asosiy holat (base case)
  3. return 1;
  4. long qolgani = faktorial(n - 1); // o‘zini chaqiradi
  5. return n * qolgani;
  6. }
StackOverflowError
Stek hajmi cheklangan (odatda ~512 KB–1 MB, -Xss bilan). Base case bo‘lmasa yoki juda chuqur rekursiya (masalan 100 000) — StackOverflowError. Chuqur bo‘lishi mumkin bo‘lsa — sikl bilan yozing (92-dars, DSA).
07

Java har doim “pass-by-value”

Metodga har doim qiymatning nusxasi beriladi. Primitivda — sonning nusxasi; obyektda — havolaning (manzilning) nusxasi. Shuning uchun obyekt ichini o‘zgartirish ko‘rinadi, havolani boshqa obyektga yo‘naltirish — yo‘q.

PassByValue.java
  1. static void ozgartir(int x, StringBuilder sb, List<Integer> l) {
  2. x = 99; // nusxa o‘zgardi
  3. sb.append("!"); // obyekt o‘zgardi
  4. l = new ArrayList<>(); // faqat nusxa-havola yangi obyektga
  5. l.add(7); // asl ro‘yxatga ta’sir yo‘q
  6. }
  7. public static void main(String[] a) {
  8. int son = 5;
  9. StringBuilder s = new StringBuilder("Salom");
  10. List<Integer> ro = new ArrayList<>(List.of(1));
  11. ozgartir(son, s, ro);
  12. System.out.println(son + " " + s + " " + ro); // 5 Salom! [1]
  13. }
08

Suhbat savollari

?Java pass-by-value mi yoki pass-by-reference?
Doim pass-by-value. Primitivda qiymat nusxalanadi. Obyektda manzil (reference) nusxalanadi — shuning uchun obyekt ichini o'zgartirsa (user.setName()) tashqarida ko'rinadi, lekin parametrni yangi obyektga tayinlasa (user = new User()) tashqarida ko'rinmaydi. Bu eng ko'p adashtiradigan savol.
?Overloading va overriding farqi?
Overloading — bir class'da bir nomli, turli parametrli metodlar (compile-time). Overriding — ota-class metodini vorisda qayta yozish (runtime, 10-modul). Overload — parametrlar farqli, override — imzo bir xil.
?StackOverflowError qachon chiqadi?
Rekursiya to'xtamasa (base case yo'q yoki noto'g'ri), har chaqiruv Stack'ga yangi ramka qo'shadi va Stack to'lib ketadi. Yechim — har rekursiyada aniq to'xtash sharti bo'lishi.
?static metod nima va qachon?
Obyektga bog'liq bo'lmagan metod — class orqali to'g'ridan chaqiriladi (Math.max). Obyekt holatiga tegmaydigan yordamchi funksiyalar uchun. static metod instance maydonlariga kira olmaydi (obyekt yo'q).
?Rekursiya qanday ishlaydi va xavfi nima?›
Har chaqiruv call stack’ka yangi kadr (parametrlar, lokal o‘zgaruvchilar, qaytish manzili) qo‘shadi; base case’ga yetgach kadrlar teskari tartibda yopiladi. Xavf: base case yo‘q yoki juda chuqur → StackOverflowError. Java’da tail-call optimizatsiya yo‘q — chuqur rekursiyani siklga aylantiring.
?Stack va heap’da nima saqlanadi?›
Stack (har thread’ga alohida): metod kadrlari, primitiv lokal o‘zgaruvchilar, havolalar. Heap (umumiy): barcha obyektlar va massivlar, GC boshqaradi. Lokal havola stackda, u ko‘rsatgan obyekt heapda.
?Metod ichida String parametrini o‘zgartirsam, chaqiruvchi ko‘radimi?›
Yo‘q. s = s + "!" yangi String obyekt yaratadi va faqat lokal nusxa-havolani unga yo‘naltiradi; String immutable. StringBuilder’ni append qilish esa ko‘rinadi.
?Overloading qanday hal qilinadi?›
Kompilyatsiya vaqtida, argumentlarning statik tiplari bo‘yicha: aniq moslik → widening (int→long) → boxing → varargs. Qaytish tipi farqi overloading uchun yetarli emas.
