03

Vaziyatli savollar

Tajribani tekshiradigan savollar. Javobni ochishdan oldin o‘zingiz 1 daqiqa o‘ylang.

?Mijoz qidiruv maydoniga "Otabek" yozdi, lekin natijalarda "Ota" bo‘yicha natija ko‘rinib qoldi. Nima bo‘ldi?›
Poyga holati: har harfga so‘rov ketgan, "Ota" javobi "Otabek" javobidan keyin keldi va uni bosib ketdi. Yechim: debounce (300 ms), oldingi so‘rovni AbortController bilan bekor qilish, yoki javobni faqat oxirgi so‘rov ID’siga mos kelsa qabul qilish.
?"To‘lash" tugmasi ikki marta bosildi — ikki to‘lov ketdi. Frontend va backend’da nima qilasiz?›
Frontend: so‘rov davomida tugmani disabled, once/flag, loading holati. Backend (asosiy himoya!): Idempotency-Key sarlavhasi (UUID, frontend har to‘lov uchun bitta yaratadi) + DB’da UNIQUE — ikkinchi so‘rov birinchisining natijasini qaytaradi. Frontend himoyasi yetarli emas (tarmoq retry, ikki tab).
?SPA bir necha soat ochiq tursa sekinlashib, xotira 1 GB ga yetadi. Qanday qidirasiz?›
Chrome DevTools → Memory: heap snapshot’lar solishtirish (Comparison), Detached DOM tree’lar, retainers zanjiri. Tipik sabablar: tozalanmagan setInterval/listener (window’da), global massivga yig‘ilayotgan ma’lumot, closure ushlab turgan katta obyektlar, o‘chirilgan komponentga havola. Vue’da onUnmounted’da tozalash.
?Sahifa "qotib qoladi" — tugmalar 2–3 soniya javob bermaydi.›
Performance tab’da Long Task’larni topish (sariq bloklar > 50 ms): katta JSON parse, 10 000 qatorli ro‘yxatni render, sinxron hisob. Yechimlar: virtual scroll, pagination, Web Worker, hisobni bo‘laklash, kerakli ma’lumotni backend’dan filtrlab olish.
?Backend’dan kelgan hisob ID 9007199254740993 frontend’da boshqa songa aylandi.›
Number 2⁵³ dan katta butun sonni aniq saqlay olmaydi. Yechim: API’da ID’larni string sifatida yuborish (Jackson ToStringSerializer yoki DTO’da String), frontend’da BigInt faqat hisob kerak bo‘lsa.
?Frontend dasturchisi "CORS xatosi bor, backend tuzatsin" dedi. Nimalarni tekshirasiz?›
Network tab: preflight OPTIONS bormi va statusi (401/403 — Security filtri preflight’ni to‘sgan), javobda Access-Control-Allow-Origin aniq origin bilan bormi (credentials bilan "*" ishlamaydi), Allow-Headers’da Authorization bormi, reverse proxy (nginx) sarlavhalarni o‘chirmayaptimi. Spring’da http.cors() + CorsConfigurationSource.
?Access token’ni localStorage’da saqlash haqida fikringiz?›
XSS bo‘lsa har qanday skript o‘qib oladi. Yaxshiroq: BFF (token’lar serverda, brauzerda HttpOnly SameSite cookie) yoki kamida token’ni xotirada saqlash + qisqa muddat + silent refresh, qat’iy CSP. Bankda — BFF.
?"async/await ishlatgan edim, lekin so‘rovlar baribir sekin." Nimaga qaraysiz?›
Mustaqil await’lar ketma-ket yozilganmi (Promise.all kerak), forEach ichida async, waterfall so‘rovlar (bittasi tugab keyingisi — backend’da bitta endpoint yaxshiroq), keraksiz qayta so‘rovlar (kesh yo‘q), katta javob hajmi.
