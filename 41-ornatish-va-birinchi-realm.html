06
Birinchi token — curl bilan

    
Eng oddiy flow — client_credentials: tolov-service servisi o'z nomidan token oladi (foydalanuvchisiz). So'rovni yuboring.

    
terminal


curl -s -X POST http://localhost:8080/realms/bank/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=tolov-service \
  -d client_secret=svc-secret-change-me

    

    
Javob shu yerda.

    

    
⚠ Password grant haqida
Internetda grant_type=password&username=...&password=... misollari juda ko'p. Bu Resource Owner Password grant — OAuth 2.1'da olib tashlangan: ilova foydalanuvchi parolini ko'radi, MFA ishlamaydi. Faqat lokal test uchun (client'da "Direct access grants" yoqilgan bo'lsa). Haqiqiy login — Authorization Code + PKCE (43-modul).

Qo'lda bosib-bosib sozlash — takrorlanmaydi va git'da iz qoldirmaydi. Realm'ni JSON qilib saqlang: compose'dagi ./realm papkasiga qo'ysangiz, --import-realm uni birinchi ishga tushishda yuklaydi.

    
realm/bank-realm.json

    

      
Eksport qilish
docker compose exec keycloak /opt/keycloak/bin/kc.sh export --realm bank --dir /opt/keycloak/data/import --users realm_file
Tayyor bo'lgach, JSON'dagi parol va sirlarni tozalang — git'ga sir yozilmaydi.

      
Kod sifatida (IaC)
Katta jamoalarda: keycloak-config-cli (JSON/YAML dan idempotent qo'llash) yoki Terraform keycloak provider. Admin konsol — faqat ko'rish uchun, o'zgarishlar PR orqali.

    

    
💡 kcadm.sh — Admin CLI
kcadm.sh config credentials --server http://localhost:8080 --realm master --user admin → kcadm.sh create users -r bank -s username=dilnoza -s enabled=true. Skriptlar va CI uchun qulay. Xuddi shu ishni Admin REST API ham qiladi: POST /admin/realms/bank/users.

  


  

    
08
Suhbat savollari

    

      
?Keycloak ma'lumotlarini qayerda saqlaydi? H2'da qolsa nima bo'ladi?›
Realm, user, client va sozlamalar tashqi relatsion bazada (PostgreSQL, MySQL, Oracle, MSSQL). Dev rejimda default — ichki H2 fayl: konteyner o'chsa, hamma narsa yo'qoladi va klaster qurib bo'lmaydi. Prod'da doim tashqi DB kerak, zaxira nusxasi va HA bilan.

      
?Issuer URL qanday aniqlanadi va nega muhim?›
{hostname}/realms/{realm}. Tokenning iss claim'i aynan shu qiymat. Resource server issuer-uri bilan solishtiradi va discovery orqali JWKS'ni topadi. Hostname noto'g'ri bo'lsa (ichki docker nomi, http o'rniga https), tokenlar rad etiladi. Prod'da KC_HOSTNAME doim aniq beriladi.

      
?Keycloak sozlamalarini muhitlar orasida (dev→test→prod) qanday ko'chirasiz?›
Realm JSON git'da saqlanadi va sirlar placeholder bilan almashtiriladi. keycloak-config-cli yoki Terraform bilan CI'da qo'llanadi. Sirlar vault/secret manager'dan keladi. Admin konsolda qo'lda o'zgartirish faqat dev'da.

      
?/.well-known/openid-configuration nima?›
OIDC Discovery hujjati: issuer, authorization/token/userinfo/end_session endpoint'lari, jwks_uri, qo'llab-quvvatlanadigan grant va algoritmlar. Kutubxonalar faqat issuer'ni bilib, qolganini shu yerdan avtomatik oladi — endpoint'larni qo'lda yozish shart emas.
