Token ichida: JWT, RS256, JWKS

Keycloak'ning access tokeni — imzolangan JSON. API uni har so'rovda Keycloak'ka murojaat qilmasdan, lokal tekshiradi. Buning uchun ichida nima borligini, imzo qanday tekshirilishini va kalitlar qanday almashtirilishini aniq bilish kerak. 32-modulda JWT'ning umumiy tuzilishini ko'rgan edik, bu yerda — haqiqiy Keycloak tokeni.

07

Suhbat savollari

?Resource server JWT'ni qanday validatsiya qiladi?›
1) Format: 3 qism, Base64URL. 2) Header: alg kutilganiga teng (RS256), none va HS* rad etiladi. 3) kid bo'yicha JWKS keshidan public kalit; topilmasa — JWKS'ni qayta yuklash (rate limit bilan). 4) Imzo. 5) exp, nbf, iat — kichik clock skew bilan. 6) iss — aniq realm URL. 7) aud — shu API. 8) Scope va rollar — endpoint talabiga ko'ra.
?alg: none hujumi nima?›
Hujumchi header'ni {"alg":"none"} qilib, imzoni olib tashlaydi. Zaif kutubxona "imzo shart emas" deb qabul qiladi. Yana biri — algorithm confusion: RS256 public kalitini HS256 siri sifatida ishlatish. Himoya: kutilgan algoritmni server tomonda qat'iy belgilash, headerdagi alg'ga ishonmaslik. Spring (Nimbus) sukut bo'yicha to'g'ri qiladi.
?Kalit rotatsiyasi token tekshiruvini qanday buzmaydi?›
Keycloak'da bir vaqtda bir nechta kalit bo'ladi: yangisi active (imzolaydi), eskisi passive (JWKS'da qoladi, faqat tekshiruv uchun). Token header'idagi kid qaysi kalitni ishlatishni aytadi. API noma'lum kid ko'rsa, JWKS'ni qayta yuklaydi. Eski kalit eng uzun token (refresh/offline) muddati o'tgandan keyin olib tashlanadi.
?Access token nega qisqa bo'lishi kerak?›
JWT lokal tekshiriladi va uni darhol bekor qilib bo'lmaydi. O'g'irlangan yoki bekor qilingan token exp'gacha ishlayveradi. Qisqa (5 daqiqa) muddat xavf oynasini kichraytiradi, refresh token esa qulaylikni saqlaydi. Refresh token Keycloak'da har safar tekshiriladi, shuning uchun uni bekor qilish darhol ta'sir qiladi.
?aud claim nima uchun kerak?›
Token qaysi API uchun chiqarilganini bildiradi. Tekshirilmasa, "Byudjet" ilovasiga berilgan token tolov-service'da ham ishlaydi (confused deputy / token replay). Keycloak'da Audience mapper yoki client scope orqali aud'ga kerakli servislarni qo'shasiz, API esa o'z nomini tekshiradi.
