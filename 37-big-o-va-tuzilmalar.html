Big-O va ma'lumot tuzilmalari

"Bu kodning murakkabligi qancha?" — deyarli har texnik suhbatda so'raladi. Big-O — kod n marta kattaroq ma'lumotda qanchaga sekinlashishini aytadigan til. Grafikda ko'ring, poygada his qiling, kodda toping.

01

O'sish egri chiziqlari — n oshganda nima bo'ladi

n — ma'lumot hajmi (satrlar, elementlar). Slayderni suring — har algoritm nechta amal qilishini ko'ring. Legenda'ni bosib chiziqni yashiring.

n = 100
🎯 Suhbatda qoida
Big-O — eng yomon holat, eng katta had (O(n² + n) = O(n²)), konstantasiz (O(3n) = O(n)). "Amalda 3n va n farq qiladi" — ha, lekin Big-O o'sish tezligini solishtiradi, mutlaq vaqtni emas.

05

Klassik: Two Sum — O(n²) dan O(n) ga

Massivda yig'indisi 14 bo'lgan juftlikni toping. Ikki yondashuvni ishga tushiring.

Amallar: 0
TwoSum.java
// O(n²): har juftlikni tekshirish
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == target) return new int[]{i, j};

// O(n): "menga kerak bo'lgan juftni oldin ko'rganmanmi?"
Map<Integer,Integer> seen = new HashMap<>();
for (int i = 0; i < n; i++) {
    int kerak = target - a[i];
    if (seen.containsKey(kerak)) return new int[]{seen.get(kerak), i};   // O(1)
    seen.put(a[i], i);
}
// Xotira: O(n) — vaqtni xotiraga almashtirdik (klassik trade-off)
06

Suhbat savollari

?Big-O nima? O(1), O(log n), O(n), O(n log n), O(n²) ga misol.›
Kirish hajmi oshganda amallar sonining o'sish tartibi (yuqori chegara). O(1) — HashMap.get, massiv indeks. O(log n) — binar qidiruv, TreeMap, B-tree indeks. O(n) — ro'yxatni aylanish, contains(ArrayList). O(n log n) — saralash (Collections.sort — TimSort). O(n²) — ichma-ich sikl, bubble sort. O(2ⁿ) — rekursiv Fibonacci (memo'siz).
?ArrayList va LinkedList: qachon qaysi?›
ArrayList: get(i) O(1), oxiriga add amortized O(1), o'rtaga insert O(n) (siljitish), xotira zich, CPU cache do'st. LinkedList: o'rtaga insert O(1) — lekin o'sha joyga yetib borish O(n); get(i) O(n); har element uchun qo'shimcha 2 pointer. Amalda deyarli doim ArrayList; queue/deque kerak bo'lsa — ArrayDeque.
?HashMap O(1) — har doimmi?›
O'rtacha O(1). Yomon hashCode (hamma bir bucket'ga) → O(n); Java 8+ bucket 8 dan oshsa daraxtga aylanadi → O(log n). Load factor 0.75 dan oshganda resize (O(n) bir martalik). Kalit immutable va equals/hashCode to'g'ri bo'lishi shart (12-modul).
?HashMap va TreeMap farqi?›
HashMap — O(1), tartibsiz. TreeMap — qizil-qora daraxt, O(log n), kalitlar tartiblangan: firstKey, floorKey, subMap (diapazon). "Eng yaqin kurs sanasi" kabi savollar — TreeMap. LinkedHashMap — qo'shilish tartibi, LRU cache uchun (accessOrder=true + removeEldestEntry).
?Amortized O(1) nima?›
Ba'zi amallar qimmat (ArrayList to'lganda ×1.5 nusxalash O(n)), lekin kam uchraydi; o'rtacha har add O(1) ga to'g'ri keladi. n ta add uchun jami O(n).
?Xotira murakkabligi (space) nima? Vaqt-xotira almashuvi?›
Algoritm qo'shimcha qancha xotira oladi. Two Sum: O(n²) vaqt / O(1) xotira ↔ O(n) vaqt / O(n) xotira (HashMap). Cache, memoization, indeks — hammasi "xotira sarflab vaqt yutish".
?Stack va Queue — Java'da qaysi klass?›
ArrayDeque ikkalasi uchun (push/pop, offer/poll) — Stack klassi eskirgan (synchronized, Vector). PriorityQueue — heap, eng kichik O(log n) da. Producer-consumer: BlockingQueue (22-modul).
