Promise va async/await

fetch, fayl o‘qish, taymer — hammasi Promise qaytaradi: "natija hozir yo‘q, keyin bo‘ladi" degan va’da. Java’dagi CompletableFuturening JS’dagi ukasi. async/await esa Promise’larni oddiy ketma-ket kod kabi yozish imkonini beradi. Bu modulda holatlar, zanjirlar, parallel so‘rovlar va xatolarni ushlashni ko‘ramiz.

01

Promise faqat bir marta hal bo‘ladi: pending → fulfilled yoki pending → rejected. Undan keyingi resolve/reject chaqiruvlari e’tiborsiz qoldiriladi. Sinab ko‘ring.

02

Zanjir: qiymat va xato qanday oqadi

fetch → json → hisobla → ko‘rsat → catch → finally. Xato qaysi bosqichda bo‘lishini tanlang va "Oqim"ni bosing.

⚠️ Eng ko‘p uchraydigan xato
.then(r => { r.json(); }) — figurali qavs bilan return unutilgan: keyingi .then undefined oladi. Arrow’ning qisqa shakli r => r.json() avtomatik qaytaradi. Va yana: fetch 404/500 da reject qilmaydi — faqat tarmoq xatosida. if (!r.ok) throw … o‘zingiz yozasiz (73-modul).

04

await: ketma-ket yoki parallel?

Uchta mustaqil so‘rov (har biri ~500 ms). Ikki xil yozuvni solishtiring.

❌ Ketma-ket
const kurs  = await getKurs();
const bal   = await getBalans();
const kesh  = await getKeshbek();
✅ Parallel
const [kurs, bal, kesh] = await Promise.all([
  getKurs(), getBalans(), getKeshbek()
]);
So‘rovlar bir-biriga bog‘liq bo‘lmasa (ikkinchisi birinchisining natijasini talab qilmasa) — parallel yuboring.
api.js — async/await, xato, timeout, bekor qilish
async function bankSahifa(signal) {
  try {
    const [kurs, balans] = await Promise.all([
      getJson("/api/kurslar", { signal }),
      getJson("/api/hisob/balans", { signal }),
    ]);
    return { kurs, balans };
  } catch (e) {
    if (e.name === "AbortError") return null;       // foydalanuvchi sahifadan chiqib ketdi
    throw new Error("Bosh sahifa yuklanmadi", { cause: e });
  } finally {
    spinner.hide();                                  // har holda
  }
}

// Timeout: 5 s dan keyin avtomatik bekor
const data = await bankSahifa(AbortSignal.timeout(5000));

// Qidiruv: yangi harf kiritilganda eski so'rovni bekor qilish
let ctrl;
input.oninput = async () => {
  ctrl?.abort();
  ctrl = new AbortController();
  natija.value = await getJson(`/api/mijoz?q=${input.value}`, { signal: ctrl.signal }).catch(() => null);
};

06

Suhbat savollari

?Promise nima va qanday holatlari bor?›
Kelajakdagi natija uchun obyekt: pending, fulfilled (qiymat bilan), rejected (sabab bilan). Bir marta hal bo‘ladi (settled) va o‘zgarmaydi. then/catch/finally handler’lari microtask sifatida chaqiriladi.
?Promise.all, allSettled, race, any farqi?›
all — hammasi muvaffaqiyatli bo‘lsa natijalar massivi; bittasi reject bo‘lsa darhol reject (qolganlari to‘xtamaydi!). allSettled — hammasi tugashini kutadi, har birining holati va qiymati/sababi. race — birinchi hal bo‘lgan (muvaffaqiyat yoki xato). any — birinchi muvaffaqiyatli; hammasi xato bo‘lsa AggregateError.
?async/await va then farqi?›
Mexanizm bir xil — async funksiya Promise qaytaradi, await — then’ning sintaktik qulayligi. await bilan kod ketma-ket o‘qiladi, try/catch bilan xato ushlanadi, stack trace tushunarliroq. then bilan zanjirlar va kombinatorlar qulay. Ko‘pincha aralash ishlatiladi.
?Promise’ni bekor qilish mumkinmi?›
Promise’ning o‘zini — yo‘q. Manbani bekor qilish kerak: fetch va ko‘p API’lar AbortController signalini qabul qiladi; timeout uchun AbortSignal.timeout(ms). Aks holda natija kelsa ham e’tiborsiz qoldirish (flag).
?Callback hell nima va Promise uni qanday hal qiladi?›
Ichma-ich callback’lar — o‘qish qiyin, xatolar har darajada alohida. Promise zanjiri tekis struktura va bitta catch beradi; async/await esa sinxron ko‘rinishdagi kod.
?Promise.all’da bitta so‘rov xato bersa, qolganlari to‘xtaydimi?›
Yo‘q — ular davom etadi, faqat natijalari e’tiborga olinmaydi. Haqiqatan to‘xtatish uchun umumiy AbortController bilan qolganlarini abort qilish kerak.
