Generics

List<String> dagi <String> nima? Generics — kolleksiya (yoki class) ichida qanday tip borligini oldindan aytish. Kompilyator shuni majburlaydi — xato ishga tushishdan oldin tutiladi.

01

Muammo: generics'siz dunyo

Eski.java
// Java 5 dan oldin — hamma narsa Object edi
List list = new ArrayList();
list.add("Salom");
list.add(42);            // son ham kiradi — hech kim to'xtatmaydi

String s = (String) list.get(1);  // 💥 ClassCastException — ishga tushganda!

// Generics bilan — kompilyator himoyalaydi
List<String> list = new ArrayList<>();
list.add(42);            // ❌ kompilyatsiya xatosi — darhol!
String s = list.get(0);   // cast kerak emas ✓
02

Tip-xavfsiz quti — sindirib ko'ring

Box<T> — T o'rniga qaysi tipni tanlasangiz, quti faqat shuni qabul qiladi. Tipni tanlang, keyin turli narsalarni solib ko'ring. Noto'g'ri tip — kompilyator rad etadi.

Box<String>
bo'sh
Tipni tanlab, narsalarni solib ko'ring.
Box.java
class Box<T> {              // T — tip parametri (placeholder)
    private T qiymat;
    void put(T q) { qiymat = q; }
    T get() { return qiymat; }
}
Box<String> b = new Box<>();  // endi T = String
03

Generic metod va bounded type

Metod ham generic bo'lishi mumkin. <T extends Number> — T faqat Number yoki uning vorisi bo'lsin (chegaralangan tip).

Bounded.java
// generic metod — istalgan tip uchun bitta kod
static <T> void chopEt(T x) { System.out.println(x); }

// bounded — faqat sonlar (Integer, Double, ...)
static <T extends Number> double ikkilangan(T n) {
    return n.doubleValue() * 2;   // Number metodlariga kirsa bo'ladi
}
ikkilangan(5);       // ✓ Integer
ikkilangan("salom"); // ❌ String Number emas
04

Wildcard — ? extends / ? super (PECS)

Suhbatning eng nozik savoli. List<? extends Number> — "Number yoki vorislari" (o'qish uchun). List<? super Integer> — "Integer yoki otalari" (yozish uchun). Qoida: PECS — Producer Extends, Consumer Super. Nima qilmoqchisiz?

Kolleksiyadan nima qilmoqchisiz?
Object

eslab qoling
PECS: kolleksiya sizga beradi (producer) → ? extends. Siz kolleksiyaga berasiz (consumer) → ? super. Ikkovi ham kerak bo'lsa — wildcard'siz aniq tip.
05

Type erasure — generics runtime'da yo'q

Muhim ichki fakt: generics faqat kompilyatsiya paytida tekshiriladi. Kompilyatordan keyin List<String> oddiy Listga aylanadi — tip ma'lumoti "o'chiriladi" (erasure). Shuning uchun ba'zi narsalar mumkin emas.

Erasure.java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
a.getClass() == b.getClass()   // true! runtime'da ikkovi shunchaki ArrayList

new T();              // ❌ mumkin emas — T runtime'da noma'lum
if (x instanceof List<String>)  // ❌ mumkin emas
List<int>             // ❌ primitiv bo'lmaydi — List<Integer> kerak
06

Suhbat savollari

?Generics nima uchun kerak?
Tip xavfsizligi (compile-time tekshiruv — noto'g'ri tip darhol xato), cast kerak emas (kod tozaroq), va bitta kod turli tiplar uchun qayta ishlatiladi (Box<T>). Generics'siz ClassCastException runtime'da chiqardi.
?? extends va ? super farqi (PECS)?
? extends T — T yoki vorislari; kolleksiyadan o'qish mumkin, yozish yo'q (aniq qaysi voris ekani noma'lum). ? super T — T yoki otalari; kolleksiyaga T yozish mumkin, o'qish faqat Object sifatida. Producer Extends, Consumer Super.
?Type erasure nima?
Kompilyator generics tipini tekshirgach, bytecode'da uni o'chiradi — List<String> oddiy List bo'lib qoladi. Eski Java bilan moslik uchun qilingan. Oqibati: new T(), instanceof List<String>, generic massiv mumkin emas; primitivlar (int) generics'da ishlatilmaydi.
?List<Object> ga List<String> berish mumkinmi?
Yo'q. Generics invariant — String Object'ning vorisi bo'lsa ham, List<String> List<Object>ning vorisi emas. Aks holda List<Object>ga Integer qo'shib, String ro'yxatini buzish mumkin bo'lardi. Buning uchun List<? extends Object> ishlatiladi.
