OAuth 2.0 va OpenID Connect

Keycloak bilan ishlashda eng ko'p so'raladigan narsa — protokolning o'zi. OAuth 2.0 "ruxsat berish"ni hal qiladi (kimga, nimaga, qancha muddatga). OpenID Connect uning ustiga "bu kim" degan qatlamni qo'shadi. Avval nega kerakligini, keyin qanday tuzilganini ko'ramiz.

"OAuth nima uchun yaratilgan?" — Delegated authorization: foydalanuvchi uchinchi tomon ilovasiga o'z resurslariga cheklangan (scope), vaqtinchalik (expiry) va bekor qilinadigan kirish huquqini beradi, parolini bermasdan. Autentifikatsiya uchun yaratilmagan — buni OIDC qo'shgan.

3 ta token — kim uchun, nima uchun

Eng ko'p uchraydigan xato — tokenlarni chalkashtirish. Kartaga bosing.

Access token
Kim uchun: API (resource server)
Nima: "bu so'rovga ruxsat bor"
Muddat: qisqa, 5 daq
Qayerda: Authorization: Bearer
Refresh token
Kim uchun: faqat Keycloak
Nima: "yangi access token ber"
Muddat: uzun (sessiya)
Qayerda: faqat token endpoint'ga
ID token
Kim uchun: client (ilovaning o'zi)
Nima: "kim login qildi"
Muddat: qisqa
Qayerda: ilova ichida, API'ga emas
Kartani tanlang.
⚠ Klassik xato
ID token'ni API'ga Bearer qilib yuborish. ID token client uchun (aud = client_id), unda API uchun ruxsat (scope, audience) yo'q. API faqat access token qabul qiladi. Teskari xato ham bor: access token ichidan foydalanuvchi ma'lumotini "o'qish" — client uchun access token shaffof emas deb qaralishi kerak (format o'zgarishi mumkin).

Scope va consent — ilova nimani so'raydi

Chapda "Byudjet" ilovasining Keycloak'dagi rozilik sahifasi. Scope'larni belgilang va o'ngda API qaysi so'rovga ruxsat berishini ko'ring.

"Byudjet" ilovasi quyidagilarni so'ramoqda:
Token scope → API javobi
💡 Scope va rol farqi
Scope — ilovaga nima ruxsat berilgani (foydalanuvchi rozi bo'ldi): transactions:read. Rol — foydalanuvchining o'zi nima qila oladi: KASSIR. Yakuniy huquq — ikkalasining kesishmasi: kassirning tokeni faqat transactions:read scope bilan kelgan bo'lsa, o'tkazma qila olmaydi.
07

Front-channel va back-channel

🌐 Front-channel (brauzer orqali)

Redirect'lar, URL parametrlari. Brauzer tarixi, proksi loglar, kengaytmalar — hammasi ko'radi. Shuning uchun bu yerdan faqat bir martalik, qisqa muddatli kod o'tadi, token emas.

🔒 Back-channel (server → server)

Ilova serveri Keycloak'ka to'g'ridan-to'g'ri HTTPS POST qiladi, client_secret (yoki PKCE verifier) bilan. Tokenlar faqat shu yerda beriladi. Eski Implicit flow tokenni front-channel'da berardi — shuning uchun u taqiqlangan.

08

Suhbat savollari

?OAuth 2.0 va OIDC farqi?›
OAuth 2.0 — authorization (delegatsiya) framework'i: client resursga kirish uchun access token oladi. OIDC — OAuth 2.0 ustidagi identity qatlami: scope=openid bilan qo'shimcha id_token (JWT) beradi, standart claim'lar, /userinfo, discovery va logout'ni standartlashtiradi. "OAuth bilan login qilish" aslida OIDC.
?Access, refresh va ID token farqi?›
Access — API uchun, qisqa, Bearer header'da. Refresh — faqat authorization server'ga, yangi access olish uchun, uzunroq, maxfiy saqlanadi. ID — client uchun, autentifikatsiya natijasi (kim, qachon, qanday kirdi), API'ga yuborilmaydi.
?Scope va rol qanday farq qiladi?›
Scope — ilovaga berilgan ruxsat doirasi (foydalanuvchi va client kelishuvi). Rol — foydalanuvchining tashkilotdagi huquqi. API ikkalasini ham tekshiradi: hasAuthority('SCOPE_transactions:read') and hasRole('KASSIR'). Keycloak'da client scope'lar tokenga qaysi rol va claim'lar tushishini ham boshqaradi.
?Nega kod front-channel'dan, token back-channel'dan?›
Brauzer URL'lari ko'p joyda qoladi (tarix, Referer, log). Kod bir martalik, qisqa muddatli (daqiqa ichida) va uni tokenga almashtirish uchun client autentifikatsiyasi yoki PKCE verifier kerak — o'g'irlangan kod yolg'iz o'zi foydasiz. Token esa to'g'ridan-to'g'ri ishlatiladi, shuning uchun faqat server-server kanalida beriladi.
?Bearer token nima degani?›
"Kim ko'tarib yursa, o'shaniki" — token egasini qo'shimcha isbotlash talab qilinmaydi. Shuning uchun faqat HTTPS, qisqa muddat, loglarga yozmaslik. Kuchliroq variant — sender-constrained tokenlar: DPoP yoki mTLS-bound, bunda token faqat ma'lum kalit egasida ishlaydi (Keycloak qo'llaydi, FAPI talablari).
