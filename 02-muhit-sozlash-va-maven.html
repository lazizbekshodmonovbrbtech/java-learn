Muhit sozlash va Maven

Endi qo'lni ishga solamiz. JDK o'rnatish, IDE, package/import, va nega har jiddiy loyiha Maven yoki Gradle ishlatadi. Real backend loyihasi aynan shu tuzilmadan boshlanadi.

01

JDK o'rnatish va tekshirish

Birinchi qadam — JDK o'rnatish (1-modulda ko'rdik: dastur yozish uchun kerak). Yangi loyihaga LTS versiya — masalan 21 — va bepul Temurin yoki OpenJDK tavsiya etiladi. O'rnatilganini shunday tekshirasiz:

terminal
$ java -version
openjdk version "21.0.2" 2024-01-16 LTS
OpenJDK Runtime Environment Temurin-21.0.2

$ javac -version # kompilyator ham borligini tekshirish
javac 21.0.2
ko'p uchraydigan muammo
"java: command not found" — JDK o'rnatilgan-u, lekin PATH'ga qo'shilmagan. Windows'da "Environment Variables", Mac/Linux'da ~/.zshrc orqali JAVA_HOME sozlanadi. IntelliJ o'rnatsangiz, u JDK'ni o'zi topib beradi.
02

IDE — kod muharriri

Notepad'da ham Java yozsa bo'ladi, lekin hech kim unday qilmaydi. IDE (Integrated Development Environment) — kod yozishni tezlashtiradigan aqlli muharrir: xatolarni yozayotganingizdayoq ko'rsatadi, avtomatik to'ldiradi, bir tugmada ishga tushiradi, debug qiladi.

Java uchun standart tanlov — IntelliJ IDEA (Community versiyasi bepul). Yengilroq variant — VS Code (Java kengaytmalar bilan). Eclipse ham bor, lekin yangi loyihalar odatda IntelliJ tanlaydi.

03

package — kodni tartibga solish

Loyiha o'sganda yuzlab class paydo bo'ladi. package — ularni papkalarga bo'lib, nomlar to'qnashuvining oldini oladi (xuddi kompyuterdagi papkalar kabi). Package nomi papka yo'liga to'g'ridan-to'g'ri mos keladi. Chapdagi qatorni bosing — o'ngda qaysi papkaga tushishini ko'ring.

kod ichida

package com.bank.user;
package com.bank.order;
package com.bank.config;

diskdagi papkalar

src/main/java/
└ com/
  └ bank/
    ├ user/
    ├ order/
    └ config/
Chapdagi package qatorini bosing — u qaysi papkaga to'g'ri kelishini ko'rasiz.
qoida
Package nomi odatda teskari domen bilan boshlanadi: com.kompaniya.loyiha. Bu butun dunyoda nom noyob bo'lishini kafolatlaydi.
04

import — boshqa package'dan olish

Boshqa package'dagi class'ni ishlatmoqchi bo'lsangiz, uni import qilasiz — "menga bu kerak" deb. IDE buni odatda avtomatik qo'shadi.

UserService.java
package com.bank.user;        // bu fayl qaysi package'da

import java.util.List;          // standart kutubxonadan
import com.bank.order.Order;     // o'z boshqa package'imizdan

public class UserService {
    List<Order> buyurtmalar;  // endi ikkovini ishlatsak bo'ladi
}
bilib qo'ying
java.lang package'i (String, System, Integer...) avtomatik import qilinadi — shuning uchun ularni yozganda import kerak emas. Qolganlari uchun import kerak.
05

Muammo: kutubxonalarni qo'lda qo'shish

Haqiqiy loyiha o'nlab tashqi kutubxonaga tayanadi (baza drayveri, JSON kutubxonasi, Spring...). Ularni qo'lda .jar qilib yuklab, classpath'ga qo'shish — dahshat: har biri yana boshqa kutubxonaga bog'liq (transitive dependencies), versiyalar to'qnashadi, yangilash og'riqli. Buni "dependency hell" deyishadi.

Yechim — build tool (qurish vositasi): siz faqat "menga shu kutubxonaning shu versiyasi kerak" deb yozasiz, u qolganini — yuklab olish, bog'liqlarini topish, classpath tuzish, kompilyatsiya, test, .jarga yig'ish — hammasini o'zi qiladi.

06

Maven vs Gradle

Java dunyosida ikki asosiy build tool. Ikkovi ham bir vazifani bajaradi, farq — sintaksis va moslashuvchanlik.

Maven

pom.xml (XML)
  • Eng keng tarqalgan, ayniqsa korxonalarda
  • XML — batafsil, lekin bashoratli
  • Qat'iy struktura, o'rganish oson
  • Spring Boot bilan juda ko'p ishlatiladi

Gradle

build.gradle (Groovy/Kotlin)
  • Yangiroq, moslashuvchan, tezroq (kesh)
  • Kod ko'rinishida — qisqaroq
  • Android'da standart
  • Murakkab loyihalarda kuchli
qaysi birini o'rganay?
Backend/Spring Boot uchun boshlovchiga Maven tavsiya etaman — sintaksisi ochiq va o'qish oson. Gradle'ni keyin bemalol o'zlashtirasiz. Quyida Maven bilan davom etamiz.
07

pom.xml qismlab

Maven'ning yuragi — pom.xml fayli. U loyihangizni ta'riflaydi. Rangli qismlarni bosing.

pom.xml
<groupId>com.bank</groupId>
<artifactId>user-service</artifactId>
<version>1.0.0</version>

<dependencies>
    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
        <version>42.7.1</version>
    </dependency>
</dependencies>
08

Dependency qanday keladi

Siz pom.xml'ga bitta dependency yozdingiz. Endi Maven nima qiladi? Diagrammani kuzating.

1
pom.xml o'qiladi
Maven kerakli kutubxonalar ro'yxatini ko'radi
2
Maven Central'dan izlaydi
internetdagi ulkan omborxona (repository)
3
bog'liqlarini ham yuklaydi
kutubxona yana nimaga tayansa — o'shani ham (transitive)
4
local kesh (.m2)
kompyuteringizda saqlanadi — keyingi safar internet kerak emas
5
classpath tayyor
kodingiz endi shu kutubxonani ishlatishi mumkin ✓
~/.m2/repository — yuklab olingan kutubxonalarning lokal keshi. Loyihalar o'rtasida bo'lishiladi.
09

Standart loyiha tuzilishi

Maven qat'iy struktura taklif qiladi — barcha Java loyihalari deyarli bir xil ko'rinadi. Shuning uchun boshqa loyihaga o'tsangiz ham darhol yo'nalasiz.

user-service/
├ src/main/java/ # asosiy kod shu yerda
│  └ com/bank/user/
│    ├ Main.java
│    └ UserService.java
├ src/main/resources/ # konfiguratsiya, fayllar
│  └ application.yml
├ src/test/java/ # testlar (31-modul)
├ pom.xml # Maven konfiguratsiyasi
└ target/ # kompilyatsiya natijasi (.class, .jar)
10

Suhbat savollari

?Maven nima uchun kerak?
Bog'liqliklarni (dependency) boshqarish, kodni kompilyatsiya qilish, test ishga tushirish va loyihani .jarga yig'ish uchun. Siz faqat kerakli kutubxonani e'lon qilasiz — Maven uni bog'liqlari bilan yuklab, classpath'ni o'zi tuzadi.
?package va import farqi?
package — bu fayl qayerda joylashganini bildiradi (papka yo'liga mos). import — boshqa package'dagi class'ni ishlatish uchun olib kirish. package — manzil, import — chaqiruv.
?Transitive dependency nima?
Siz qo'shgan kutubxona o'zi tayanadigan boshqa kutubxonalar. Masalan Spring Boot'ni qo'shsangiz, u o'nlab boshqa kutubxonani ham avtomatik olib keladi — siz ularni alohida yozishingiz shart emas.
?groupId, artifactId, version nima?
Har bir Maven artefaktining "manzili": groupId — tashkilot (com.bank), artifactId — loyiha nomi (user-service), version — versiya (1.0.0). Bu uchtasi birgalikda har kutubxonani noyob aniqlaydi.
?Maven dependency scope’lari?›
compile (standart, hamma joyda), provided (kompilyatsiyada bor, runtime’da server beradi — servlet-api), runtime (faqat ishlashda — JDBC drayver), test (faqat testlarda — JUnit).
?Transitive dependency konflikti qanday hal qilinadi?›
Maven “eng yaqin g‘olib” (nearest wins) qoidasi bilan. mvn dependency:tree bilan ko‘rish, yoki (Spring Boot BOM) bilan versiyani qotirish.
?mvn package va mvn install farqi?›
package — target/ ichida jar yasaydi. install — undan tashqari jar’ni lokal ~/.m2 repozitoriyga joylaydi (boshqa lokal loyihalar foydalanishi uchun). deploy — masofaviy repozitoriyga.
