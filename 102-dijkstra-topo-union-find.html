01

Dijkstra: og‘irlikli eng qisqa yo‘l

Raqamlar — masofa (km). BFS bu yerda ishlamaydi: kam qirrali yo‘l uzun bo‘lishi mumkin. Dijkstra har safar hozircha eng yaqin tugunni (min-heap) "qotiradi" va qo‘shnilariga masofani yangilaydi (relaxation).

Kirish:
Dijkstra.java
  1. Map<String, Integer> dijkstra(String s) {
  2. Map<String, Integer> dist = new HashMap<>();
  3. PriorityQueue<Object[]> pq = new PriorityQueue<>(comparingInt(e -> (int) e[1]));
  4. dist.put(s, 0); pq.offer(new Object[]{s, 0});
  5. while (!pq.isEmpty()) {
  6. var e = pq.poll(); String u = (String) e[0]; int d = (int) e[1];
  7. if (d > dist.get(u)) continue; // eskirgan yozuv
  8. for (var x : g.get(u)) { // x = (v, w)
  9. int nd = d + x.w;
  10. if (nd < dist.getOrDefault(x.v, MAX)) { // qisqaroq yo‘l topildi
  11. dist.put(x.v, nd);
  12. pq.offer(new Object[]{x.v, nd});
  13. }
  14. }
  15. }
  16. return dist;
  17. }
Manfiy og‘irlik — Dijkstra ishlamaydi
Dijkstra "qotirilgan tugun masofasi endi kamaymaydi" deb hisoblaydi — bu faqat og‘irliklar ≥ 0 bo‘lsa to‘g‘ri. Manfiy qirralar bo‘lsa (masalan, kashbek bilan narx) — Bellman-Ford, O(V·E). Murakkablik: Dijkstra + binary heap — O((V + E) log V).
02

Topologik saralash (Kahn)

Mikroservislarni deploy qilish tartibi: har biri faqat bog‘liq bo‘lganlari tayyor bo‘lgandan keyin. Har tugunning kirish darajasi (nechta narsaga bog‘liq) hisoblanadi; 0 bo‘lganlar navbatga — ularni bajaramiz va qo‘shnilarning darajasini kamaytiramiz.

Kirish:
Kahn.java
  1. List<String> topo(Map<String, List<String>> g) {
  2. Map<String, Integer> in = kirishDarajalari(g);
  3. Deque<String> q = new ArrayDeque<>();
  4. in.forEach((v, d) -> { if (d == 0) q.offer(v); });
  5. List<String> tartib = new ArrayList<>();
  6. while (!q.isEmpty()) {
  7. String u = q.poll();
  8. tartib.add(u);
  9. for (String v : g.get(u))
  10. if (in.merge(v, -1, Integer::sum) == 0) q.offer(v);
  11. }
  12. if (tartib.size() < g.size()) throw new IllegalStateException("Sikl bor!");
  13. return tartib;
  14. }
03

Union-Find: guruhlarni birlashtirish

Har guruhning "rahbari" (ildizi) bor. find(x) — rahbarni topadi, union(a, b) — ikki guruhni bitta qiladi. Yo‘lni siqish (path compression) va daraja bo‘yicha birlashtirish bilan har amal deyarli O(1).

Kirish:
UnionFind.java
  1. int[] p = new int[n], rank = new int[n]; // boshida p[i] = i
  3. int find(int x) {
  4. if (p[x] != x) p[x] = find(p[x]); // yo‘lni siqish
  5. return p[x];
  6. }
  7. void union(int a, int b) {
  8. int ra = find(a), rb = find(b);
  9. if (ra == rb) return; // allaqachon bir guruhda
  10. if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
  11. p[rb] = ra; // kichik daraxt kattasiga
  12. if (rank[ra] == rank[rb]) rank[ra]++;
  13. }

04

Suhbat savollari

?Dijkstra qanday ishlaydi va nega manfiy og‘irlikda buziladi?›
Min-heap’dan eng kichik taxminiy masofali tugunni olib, uni yakuniy deb hisoblaymiz va qo‘shnilarini "bo‘shatamiz" (relax). Bu ochko‘z qaror to‘g‘ri, chunki boshqa har qanday yo‘l kattaroq masofadan o‘tadi va og‘irliklar musbat — uzunroq bo‘ladi. Manfiy qirra bu farazni buzadi.
?Dijkstra’da heap’dagi eskirgan yozuvlar bilan nima qilinadi?›
Java PriorityQueue’da decrease-key yo‘q, shuning uchun yangi (tugun, masofa) qo‘shiladi; poll qilinganda d > dist[u] bo‘lsa — eskirgan, o‘tkazib yuboriladi (lazy deletion).
?Topologik saralash qachon mumkin emas?›
Yo‘naltirilgan grafda sikl bo‘lsa (A → B → A). Kahn’da navbat tugaganda hamma tugun chiqmagan bo‘ladi — sikl isboti. Amaliyotda: Spring bean’larida circular dependency, Maven’da modul sikllari.
?Union-Find qayerda ishlatiladi?›
Bog‘langan qismlar (dinamik qo‘shilganda), Kruskal minimal karkas daraxti, "ikki hisob bitta egadami" (umumiy telefon/qurilma), to‘rda suv oqimi, tarmoqda ulanish. Ikki optimizatsiya bilan amortizatsiyalangan O(α(n)) — amalda ≤ 4.
?Ikki shahar orasidagi eng arzon reys, ko‘pi bilan K ta to‘xtash bilan?›
Oddiy Dijkstra to‘xtashlar sonini hisobga olmaydi. Holat = (shahar, to‘xtashlar soni) bilan BFS/Dijkstra yoki Bellman-Ford’ni K+1 marta iteratsiya qilish.
