02

Nominal vs strukturaviy: ID’lar aralashib ketmasin

Java — nominal
record HisobId(long v) {}
record KartaId(long v) {}

void blokla(KartaId id) { … }

blokla(new HisobId(42));   // ❌ kompilyatsiya xatosi
TypeScript — strukturaviy
type HisobId = string;
type KartaId = string;           // ikkalasi ham shunchaki string!

function blokla(id: KartaId) { … }

const h: HisobId = "20208000100";
blokla(h);                       // ✅ jim o'tadi — xato!

05
Suhbat savollari
?Strukturaviy tiplash nima?›
Tiplar mosligi nomi yoki e’lon qilingan ierarxiyasi bo‘yicha emas, tuzilmasi (maydonlar va ularning tiplari) bo‘yicha tekshiriladi. Kerakli maydonlarga ega har qanday obyekt mos — hatto qo‘shimcha maydonlari bo‘lsa ham (literal’dan tashqari).
?Excess property check nima?›
Obyekt literali to‘g‘ridan-to‘g‘ri tipga berilganda, tipda yo‘q maydonlar xato sanaladi (imlo xatolarini ushlash uchun). O‘zgaruvchi orqali berilsa — tekshirilmaydi (strukturaviy qoida).
?interface va type farqi?›
Ikkalasi obyekt shaklini ifodalaydi. type — union, tuple, primitiv alias, mapped/conditional tiplarni ham qila oladi. interface — declaration merging va extends; xato xabarlari o‘qilishi osonroq. Obyektlar uchun ko‘pincha interface, qolgani uchun type.
?Branded type nima uchun kerak?›
Strukturaviy tiplashda bir xil primitivga asoslangan turli ma’nodagi tiplar (HisobId, KartaId) aralashib ketadi. Brand (string & { __brand: "KartaId" }) ularni kompilyatsiyada ajratadi, runtime’da esa oddiy string qoladi.
?readonly runtime’da himoya qiladimi?›
Yo‘q — faqat kompilyatsiyada. Runtime’da o‘zgarmaslik kerak bo‘lsa Object.freeze (sayoz). Vue’da readonly() — reaktiv proxy darajasida.
