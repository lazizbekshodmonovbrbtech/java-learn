Vue Router: SPA navigatsiya va himoyalangan sahifalar

SPA’da sahifa almashganda brauzer serverdan yangi HTML so‘ramaydi: Vue Router URL’ni o‘zgartiradi (History API), mos marshrutni topadi, guard’lardan o‘tkazadi va kerakli komponentni (kerak bo‘lsa — kechiktirib yuklangan JS bo‘lagini) chizadi. Bank ilovasida guard — Keycloak token va rol tekshiruvi (40-modullardagi Keycloak bilan bog‘laymiz).

01

Navigatsiya ichidan ko‘rinish

Chapda — ilova (mini brauzer), o‘ngda — har bir o‘tish bosib o‘tadigan bosqichlar. Pastdagi holatlarni o‘zgartirib, bir xil havolani bosing: qayerda to‘xtaydi?

https://bank.uz/
BoshKartalarKarta 4417O‘tkazmaAdmin/xyz
Havolani bosing. Hozir foydalanuvchi login qilmagan — himoyalangan sahifaga kirsa nima bo‘ladi?
router/index.ts
const routes: RouteRecordRaw[] = [
  { path: '/', component: Bosh },
  { path: '/kartalar', component: () => import('@/pages/Kartalar.vue'),       // lazy chunk
    meta: { auth: true } },
  { path: '/kartalar/:id(\\d+)', component: () => import('@/pages/Karta.vue'),
    props: true, meta: { auth: true } },
  { path: '/otkazma', component: () => import('@/pages/Otkazma.vue'),
    meta: { auth: true } },
  { path: '/admin', component: () => import('@/pages/Admin.vue'),
    meta: { auth: true, roles: ['admin'] } },
  { path: '/:pathMatch(.*)*', component: NotFound },
]
export const router = createRouter({ history: createWebHistory(), routes })

router.beforeEach(async (to) => {
  if (!to.meta.auth) return true
  if (!keycloak.authenticated) {
    await keycloak.login({ redirectUri: location.origin + to.fullPath })  // Keycloak'ka ketadi
    return false
  }
  await keycloak.updateToken(30)            // 30 s dan kam qolgan bo'lsa — refresh
  const roles = to.meta.roles as string[] | undefined
  if (roles && !roles.some(r => keycloak.hasRealmRole(r))) return { path: '/403' }
  return true
})
router.afterEach(to => { document.title = (to.meta.title as string) ?? 'Bank' })

03

Suhbat savollari

?SPA’da routing qanday ishlaydi?›
Router history.pushState bilan URL’ni sahifani qayta yuklamasdan o‘zgartiradi va popstate hodisasini (orqaga/oldinga) tinglaydi. URL marshrut jadvaliga moslanadi, guard’lar ishlaydi, mos komponent <RouterView> ichida render qilinadi. Brauzer serverga faqat birinchi marta (va JS bo‘laklari uchun) murojaat qiladi.
?History mode’da sahifani yangilasa 404 chiqyapti. Nega?›
Brauzer /kartalar/4417 ni serverdan so‘raydi, bunday fayl yo‘q. Server barcha noma’lum yo‘llarni index.html’ga qaytarishi kerak (nginx try_files, Spring’da forward). Yoki hash mode.
?Navigation guard turlari?›
Global: beforeEach, beforeResolve, afterEach. Marshrut darajasida: beforeEnter. Komponent ichida: onBeforeRouteLeave (saqlanmagan forma — "chiqishni tasdiqlaysizmi?"), onBeforeRouteUpdate (bir xil komponent, params o‘zgardi — /kartalar/1 → /kartalar/2).
?Keycloak bilan himoyalangan marshrutni qanday qilasiz?›
meta.auth va meta.roles; beforeEach’da keycloak.authenticated tekshiruvi, yo‘q bo‘lsa keycloak.login({ redirectUri }) (PKCE bilan Authorization Code flow), bor bo‘lsa updateToken(30) va rol tekshiruvi. Lekin asosiy himoya — backend’da JWT tekshiruvi.
?Lazy loading nima beradi?›
Har sahifa alohida JS bo‘lakka (chunk) ajraladi va faqat kerak bo‘lganda yuklanadi — boshlang‘ich bundle kichik, bosh sahifa tez ochiladi. Kamchiligi — birinchi o‘tishda kichik kechikish (prefetch yoki loading holati bilan yumshatiladi).
?/kartalar/1 dan /kartalar/2 ga o‘tildi, lekin ma’lumot yangilanmadi. Nega?›
Bir xil komponent qayta ishlatiladi — setup/onMounted qayta ishlamaydi. route.params.id ni watch qilish yoki onBeforeRouteUpdate, yoki <RouterView :key="route.fullPath">.
