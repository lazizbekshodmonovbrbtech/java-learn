Encapsulation

OOP'ning to'rt ustunidan biri: ma'lumotni yashirib, unga faqat nazorat qilingan yo'l bilan kirish. Bank hisobi buni eng yaxshi ko'rsatadi — balansni har kim o'zgartira olmasin.

01

G'oya: yashirish + nazorat

Encapsulation (inkapsulyatsiya) — obyektning ichki ma'lumotini (maydonlarini) private qilib tashqaridan berkitish, va unga faqat metodlar orqali kirishga ruxsat berish.

Nega? Chunki metod ichida qoida va tekshiruv qo'yish mumkin. Ochiq maydonga esa istalgan axmoq qiymat kelishi mumkin — hisob balansi manfiy bo'lib qolishi, yosh −5 bo'lishi. Metod bu buzilishning oldini oladi.

02

Sindirib ko'ring: ochiq vs himoyalangan

Ikki hisob: chapdagi balans public (ochiq), o'ngdagi private + setter (tekshiruvli). Manfiy son kiriting (masalan −500) va "O'rnat"ni bosing. Ochiq hisob har narsani qabul qiladi; himoyalangan hisob rad etadi.

❌ public int balans

hech qanday tekshiruv yo'q
1000
 

✓ private + setBalans()

manfiyni rad etadi
1000
 
Hisob.java
// ❌ ochiq — himoyasiz
public int balans;
hisob.balans = -500;   // hech kim to'xtatmaydi!

// ✓ private + setter — himoyalangan
private int balans;
public void setBalans(int b) {
    if (b < 0) throw new IllegalArgumentException("manfiy!");
    this.balans = b;
}
03

Access modifiers — kim qayergacha yetadi

To'rt daraja kirish nazorati. Modifikatorni bosing — u qaysi joylardan ko'rinishini yoritib beradi. Ichkaridan tashqariga: eng yopiq private, eng ochiq public.

Maydonlarni deyarli doim private qiling. Metodlarni kerak bo'lsa public. Meros uchun mo'ljallangan narsalarni protected. "default" (hech narsa yozmaslik) — faqat o'sha package ichida ko'rinadi.
04

getter, setter va immutable class

private maydonni o'qish uchun getter, yozish uchun setter yoziladi. Setter'siz maydon — faqat o'qiladigan bo'ladi. Bu immutable (o'zgarmas) class'ning asosi.

getter

getBalans() — qiymatni o'qib beradi. Odatda oddiy return.

setter

setBalans(x) — qiymat beradi, lekin avval tekshiradi (validatsiya).

Immutable.java
public final class Pul {   // immutable — hech qachon o'zgarmaydi
    private final int miqdor;   // final: bir marta beriladi

    public Pul(int miqdor) { this.miqdor = miqdor; }
    public int getMiqdor() { return miqdor; }
    // SETTER YO'Q → o'zgartirib bo'lmaydi
}
immutable nima yaxshi
O'zgarmas obyekt — thread-safe (bir vaqtda o'qishga xavfsiz), ishonchli (kimdir o'zgartirib qo'ymaydi), HashMap kaliti sifatida barqaror. String ham shu sabab immutable. Java 14+ da record immutable class'ni bir qatorda yaratadi (21-modul).
05

Suhbat savollari

?Encapsulation nima va nega kerak?
Ma'lumotni (maydonlarni) private qilib berkitish va faqat metodlar orqali kirish berish. Foydasi: (1) validatsiya qo'yasiz — noto'g'ri qiymat kirmaydi; (2) ichki tuzilishni o'zgartirsangiz tashqi kod buzilmaydi; (3) faqat o'qish/yozishni cheklaysiz.
?To'rt access modifier va farqi?
private — faqat o'sha class. default (hech narsa) — o'sha package. protected — package + vorislar. public — hamma joy. Eng yopiqdan eng ochiqqa: private → default → protected → public.
?Immutable class qanday yasaladi?
(1) class'ni final (voris o'zgartirmasin), (2) maydonlarni private final, (3) setter yozmaslik, (4) qiymatlarni faqat konstruktorda berish, (5) mutable maydonlarni himoyalangan nusxa qilib qaytarish. Yoki oddiy — record ishlatish.
?Nega maydonni public qilmaslik kerak?
public maydonga har kim istalgan qiymat bera oladi — validatsiya yo'q, ichki holat buzilishi mumkin (manfiy balans). Ichki tuzilishni keyin o'zgartirsangiz butun kod buziladi. private + metod nazoratni saqlaydi.
