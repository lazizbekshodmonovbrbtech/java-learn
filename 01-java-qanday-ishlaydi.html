Java qanday ishlaydi

Kod yozgan lahzangizdan protsessor uni bajargunicha bo'lgan butun yo'l — kompilyator, bytecode, classloader, JIT va JVM. Bir marta chuqur tushunsangiz, butun Java dunyosi mantiqan joyiga tushadi.

01

Avval: dastur nima o'zi?

Siz yozgan kod — bu shunchaki matn fayli. Protsessor (CPU) esa faqat mashina kodini — nol va birlarni — tushunadi. Demak orada tarjimon kerak. Tillar bu tarjimani turlicha qiladi, va aynan shu farq Java'ning xarakterini belgilaydi.

asosiy fikr
Java ikkala dunyodan yaxshisini oladi: kod avval bir marta bytecodega kompilyatsiya qilinadi (tekshiruv, xavfsizlik), keyin JVM uni har qanday platformada bajaradi. Shu sabab Java tez ham, ko'chma (portable) ham.

03

Classloader — bytecode qanday yuklanadi

Siz java Main deganingizda JVM darhol bajarmaydi. Avval har bir .classni uch bosqichda tayyorlaydi. Bu suhbatlarda tez-tez so'raladi. Har bosqichni bosing.

1
Loading (yuklash)
.class → xotira
.class faylini topib (classpath'dan), o'qib, xotiraga oladi. Bu class haqidagi metama'lumot Method Area'da saqlanadi. Kim yuklaydi? — ClassLoaderlar iyerarxiyasi: Bootstrap → Platform → Application.
2
Linking (bog'lash)
verify · prepare · resolve
Uch qism: Verify — bytecode buzuq yoki xavfli emasligini tekshiradi (Java xavfsizligining asosi). Prepare — static maydonlarga standart qiymat beradi (0, null, false). Resolve — ramziy havolalarni (symbolic references) haqiqiy manzillarga aylantiradi.
3
Initialization (ishga tayyorlash)
static bloklar ishlaydi
Endi static maydonlarga siz yozgan haqiqiy qiymatlar beriladi va static { } bloklar ishlaydi. Class faqat birinchi marta kerak bo'lganda initialize qilinadi — Java "dangasa" (lazy) ishlaydi, keraksiz class'larni yuklamaydi.
suhbatda
"ClassNotFoundException va NoClassDefFoundError farqi?" — birinchisi class'ni yuklash paytida topilmasa (ko'pincha reflection), ikkinchisi kompilyatsiyada bor edi-yu, ishga tushishda yo'qolsa. Ikkovi ham classpath muammosi.
04

JIT — nega Java "isiydi"

Bu Java'ning eng nozik va eng ko'p savol tug'diradigan qismi. Boshida JVM bytecode'ni interpretatsiya qiladi — satrma-satr o'qib bajaradi. Bu tez ishga tushadi, lekin sekin ishlaydi.

JVM ishlash davomida qaysi kod ko'p ishlatilayotganini kuzatadi ("hot" kod). Shundaylarni JIT (Just-In-Time) kompilyator real vaqtda tezkor mashina kodiga aylantiradi va keshlaydi. Shuning uchun Java dasturi bir necha soniya "isigach" ancha tezlashadi — bu "warmup" deyiladi.

JIT bosqichlari
// C2 (Server) — eng tez, chuqur optimizatsiya
       ▲   Tier 4
       │   Tier 3  // C1 (Client) — tez kompilyatsiya
tezlik │   Tier 1
       │   Tier 0  // Interpreter — darhol, lekin sekin
       └──────────────▶ kod necha marta chaqirildi
oddiy qilib
Interpreter — "hoziroq boshla". JIT — "ko'p ishlatilganini keyin tezlashtir". Shu sabab kichik skript sifatida Java sekinroq tuyuladi, lekin uzoq ishlaydigan serverda C++'ga yaqin tezlikda ishlaydi.
05

"Bir marta yoz, hamma joyda ishla"

Bytecode'ning sehri: Main.class faylini bir marta yaratasiz, u Windows'da ham, Mac'da ham, Linux'da ham o'zgarmasdan ishlaydi. Chunki har OS'ning o'z JVM'i bor — kodni emas, JVM'ni har platformaga moslashtirishgan.

JDK, JRE, JVM — matryoshka

JDKJava Development Kit — ishlab chiqish to'plami

JREJava Runtime Environment — ishga tushirish muhiti
Tayyor dasturni faqat ishga tushirish uchun. Standart kutubxonalar shu yerda.
JVMJava Virtual Machine — virtual mashina
Bytecode'ni o'qib, tekshirib, bajaradigan dvigatel. Classloader, JIT, xotira (Heap/Stack) va Garbage Collector — hammasi shu yerda.
eslatma

08

classpath nima?

JVM class'larni qayerdan qidirishini bilishi kerak. classpath — aynan shu "qidiruv yo'llari" ro'yxati: papkalar va .jar fayllar. Boshlovchilarni eng ko'p qiynaydigan xatolar (ClassNotFoundException) deyarli har doim noto'g'ri classpath'dan.

Yaxshi xabar: Maven yoki Gradle (2-modul) va IDE buni siz uchun avtomatik boshqaradi — qo'lda classpath yozish kamdan-kam kerak bo'ladi.

09

10

Qanday ishga tushirasiz

Ikki yo'l bor. Ichini tushunish uchun terminal, kundalik ish uchun IDE.

terminal
$ javac Main.java # kompilyatsiya → Main.class hosil bo'ladi
$ java Main # JVM'da ishga tushirish
Salom, dunyo!

# Java 11+ da bitta faylni to'g'ridan ishga tushirsa ham bo'ladi:
$ java Main.java # javac'siz
amalda
Haqiqiy loyihada IntelliJ IDEA (yoki VS Code) ishlatasiz — u yozganingizni tekshiradi, avtomatik to'ldiradi, xatolarni ko'rsatadi va bir tugmada ishga tushiradi. Terminal buyruqlari esa "ich"ini tushunish uchun muhim.
11

Boshlovchilar eng ko'p qiladigan xatolar

Bularni oldindan bilsangiz — soatlab vaqt tejaysiz.

class nomi ≠ fayl nomi
Agar class Main bo'lsa, fayl Main.java bo'lishi shart (public class uchun). Aks holda kompilyatsiya xatosi.
; unutish
Java'da deyarli har amal ; bilan tugaydi. Eng ko'p uchraydigan sintaksis xatosi.
main imzosi noto'g'ri
public static void main(String[] args) — aniq shunday. Bittasi ham xato bo'lsa JVM kirish nuqtasini topolmaydi.
Katta-kichik harf
Java case-sensitive: String ≠ string, Main ≠ main. Kompilyator buni kechirmaydi.
12

Suhbat savollari

Bu modul bo'yicha eng ko'p so'raladigan savollar. Har birini ochib javobni ko'ring — o'z so'zingiz bilan aytishga harakat qiling.

?Java kompilyatsiyalanadimi yoki interpretatsiyalanadimi?
Ikkalasi ham. Avval javac bilan bytecodega kompilyatsiya qilinadi, keyin JVM uni interpretatsiya qiladi va issiq qismlarini JIT bilan mashina kodiga kompilyatsiya qiladi. Shuning uchun "Java — kompilyatsiya + interpretatsiya" deb aytiladi.
?Bytecode nima va nega kerak?
Odam va mashina orasidagi oraliq til — platformaga bog'liq emas. Aynan u tufayli bitta .class hamma OS'da ishlaydi ("write once, run anywhere"). Uni har platformaning JVM'i bajaradi.
?JDK, JRE va JVM farqi?
JVM — bytecode'ni bajaradigan dvigatel. JRE = JVM + standart kutubxonalar (ishga tushirish uchun). JDK = JRE + ishlab chiqish vositalari (javac, debugger...). Bir-birining ichida: JDK ⊃ JRE ⊃ JVM.
?JIT nima qiladi?
Ish davomida ko'p ishlatiladigan ("hot") bytecode'ni real vaqtda tezkor mashina kodiga kompilyatsiya qiladi va keshlaydi. Shu tufayli Java "isigach" tezlashadi. Interpretatsiya darhol boshlaydi, JIT keyin tezlashtiradi.
?Class yuklanishining bosqichlari?
Loading (topib xotiraga olish) → Linking (verify, prepare, resolve) → Initialization (static bloklar va qiymatlar). Class faqat birinchi marta kerak bo'lganda initialize qilinadi (lazy).
