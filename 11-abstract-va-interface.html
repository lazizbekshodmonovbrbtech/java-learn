Abstract va interface

Ikki qurilish bloki — farqi qanchalik "tayyor" ekani. Interface — sof shartnoma ("nima qilish kerak"). Abstract class — yarim tayyor. Bu ikkovi katta tizimlarni moslashuvchan qiladi.

01

To'liqlik spektri

Uchtasini bir chiziqda ko'ring: interface deyarli bo'sh (faqat shartnoma), abstract class yarim tayyor, oddiy class to'liq tayyor (obyekt beradi).

interface

~0% tayyor
faqat metod nomlari (shartnoma)

abstract class

~50% tayyor
ba'zi metodlar tayyor, ba'zisi bo'sh

class

100% tayyor
hammasi tayyor, new bilan yasaladi

02

Interface — sof shartnoma

Interface faqat "qaysi metodlar bo'lishi shart"ligini aytadi, "qanday"ni emat. Class uni implements qiladi va metodlarni to'ldiradi. Bank to'lov tizimi buni yaxshi ko'rsatadi.

Tolov.java
interface Tolov {
    String tola(int summa);   // faqat shartnoma — tanasi yo'q
}

class Karta implements Tolov {
    @Override
    public String tola(int s) { return s + " so'm kartadan yechildi"; }
}
class Naqd implements Tolov {
    @Override
    public String tola(int s) { return s + " so'm naqd olindi"; }
}
03

Interfeysga "ulash" — jonli

Kod faqat Tolov interfeysini biladi. Qaysi haqiqiy amalga oshirish "ulanishini" tanlang — kod o'zgarmaydi, lekin xatti-harakat o'zgaradi. Bu — Strategy pattern va Spring DI'ning asosi.

Tolov tolov = ... (interfeys tipi)
Pastdan bittasini ulang ↓
Ulaganingizdan so'ng tolov.tola(50000) chaqiriladi.
nega bu kuchli
Kod Tolovga bog'langan, aniq class'ga emas. Ertaga yangi to'lov turi (Crypto) qo'shsangiz — mavjud kod o'zgarmaydi. Bu "programming to interface" — moslashuvchan, kengaytiriladigan dizayn. Spring butunlay shunga qurilgan (24-modul).
04

default va static metodlar

Java 8'dan interface'da default metod (tayyor tana bilan) bo'lishi mumkin — barcha amalga oshirishlar avtomatik oladi, xohlasa qayta yozadi. Bu eski interfeyslarga yangi metod qo'shishni buzmasdan imkon berdi.

Default.java
interface Tolov {
    String tola(int summa);          // abstract — majburiy

    default String chek() {              // tayyor tana — ixtiyoriy
        return "Chek chop etildi";
    }
}
05

Abstract class vs interface

Ikkovi ham to'g'ridan-to'g'ri obyekt bermaydi. Qachon qaysi biri?

abstract class

  • Umumiy holat (maydonlar) bo'lsa
  • Tayyor kod + bo'sh metod aralash
  • Faqat bittasidan extends
  • "is-a" kuchli aloqa

interface

  • Faqat xatti-harakat shartnomasi
  • Bir class ko'p interfeys oladi
  • Bog'liq bo'lmagan class'larga umumiy qobiliyat
  • "can-do" aloqa (Comparable, Runnable)
ko'p meros
Class faqat bitta class'dan extends qiladi, lekin ko'p interfeysni implements qila oladi: class Karta implements Tolov, Serializable, Comparable. Java'da "ko'p meros" aynan shunday hal qilinadi.
06

Bitta interfeys — uch xil xatti-harakat

Kod faqat Tolov interfeysini biladi. Qaysi komissiya() va nom() ishlashi — obyektga bog‘liq. Diagrammada har chaqiruvda qaysi klass “javob berayotgani” yonadi.

Tolovlar.java
  1. interface Tolov {
  2. double komissiya(double summa); // abstrakt — shartnoma
  3. default String nom() { return "To‘lov"; } // standart amalga oshirish
  4. }
  5. abstract class KartaTolov implements Tolov { // umumiy holat + kod
  6. protected final String oxirgi4;
  7. KartaTolov(String o) { oxirgi4 = o; }
  8. public String nom() { return "Karta *" + oxirgi4; }
  9. }
  10. class Humo extends KartaTolov {
  11. Humo(String o) { super(o); }
  12. public double komissiya(double s) { return s * 0.005; }
  13. }
  14. class Visa extends KartaTolov {
  15. Visa(String o) { super(o); }
  16. public double komissiya(double s) { return s * 0.015 + 1; }
  17. }
  18. class Click implements Tolov { // nom() — default
  19. public double komissiya(double s) { return 0; }
  20. }
  21. for (Tolov t : List.of(new Humo("4411"), new Visa("9001"), new Click()))
  22. System.out.println(t.nom() + ": " + t.komissiya(100));
Diamond: ikki default metod to‘qnashsa
interface A { default String salom() { return "A"; } }
interface B { default String salom() { return "B"; } }
class C implements A, B {
    @Override public String salom() {        // ❗ majburiy — aks holda kompilyatsiya xatosi
        return A.super.salom() + B.super.salom();   // aniq tanlash
    }
}

07

Suhbat savollari

?abstract class va interface farqi?
abstract class — holat (maydonlar), konstruktor, tayyor+bo'sh metodlar bo'lishi mumkin; faqat bittasidan extends. interface — asosan shartnoma (Java 8+ da default/static metod ham), maydon konstantalar; ko'p interfeysni implements qilsa bo'ladi. Umumiy holat kerak → abstract; faqat qobiliyat kerak → interface.
?Nima uchun "program to interface"?
Kodni aniq class'ga emas, interfeysga bog'lasangiz, amalga oshirishni bemalol almashtirasiz (test uchun mock, yangi tur qo'shish) va mavjud kod buzilmaydi. Bu moslashuvchanlik va bo'shbog'liqlik (loose coupling) beradi — Spring DI shunga asoslanadi.
?Interface'da default metod nega qo'shildi?
Java 8'da. Eski interfeyslarga yangi metod qo'shsangiz, barcha mavjud amalga oshirishlar buzilardi. default metod tayyor tana beradi — yangi metod qo'shilsa ham eski kod ishlayveradi (masalan Collection'ga stream() qo'shilganda).
?Bir class nechta interfeys implements qila oladi?
Istagancha (ko'p). class A implements X, Y, Z. Class'lar uchun esa faqat bitta extends. Shu sabab Java'da "ko'p meros" interfeyslar orqali amalga oshiriladi (diamond problem'ni oldini olib).
?Abstract class va interface — qachon qaysi?›
Interface — shartnoma/qobiliyat, bir nechtasini implement qilish mumkin, holatsiz; API dizaynida birinchi tanlov. Abstract class — umumiy holat (maydonlar), konstruktor, qisman tayyor kod (template method) kerak bo‘lsa. Ko‘pincha ikkalasi birga: interfeys + uni qisman amalga oshiruvchi abstract klass (AbstractList kabi).
?default metodlar nima uchun qo‘shilgan?›
Java 8’da mavjud interfeyslarni (Collection) buzmasdan yangi metod qo‘shish uchun (stream(), forEach). Diamond to‘qnashuvda klass o‘zi override qilib, A.super.m() bilan tanlaydi.
?Functional interface nima?›
Bitta abstrakt metodli interfeys (@FunctionalInterface): Runnable, Comparator, Function. Lambda shu metodni amalga oshiradi (17-dars).
?Marker interface va sealed interface?›
Marker — metodsiz (Serializable, Cloneable): tipga belgi qo‘yadi; zamonaviy alternativa — annotatsiya. Sealed (Java 17) — qaysi klasslar implement qila olishini cheklaydi; switch pattern matching’da to‘liqlikni (exhaustiveness) kompilyator tekshiradi.
