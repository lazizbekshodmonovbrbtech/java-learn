Exceptions chuqur

Dastur ideal dunyoda yashamaydi: fayl yo'qoladi, tarmoq uziladi, nol'ga bo'linadi. Java bularni exception bilan boshqaradi. Bu modulda ierarxiya, ko'tarilish, o'z exception'ingiz va professional qoidalar.

01

Ierarxiya — tugunni bosing

Hamma xatolar Throwabledan keladi. Ikki katta shox: Error (JVM darajasi, tuzatib bo'lmaydi) va Exception. Exception ichida RuntimeException (unchecked) va qolganlari (checked). Tugunni bosing.

Throwable
Error
OutOfMemoryError
Exception
IOException
RuntimeException
NPE
IllegalArgument
Tugunni bosing — u checked, unchecked yoki Error ekanini va qachon uchrashini ko'rasiz.
02

Checked vs unchecked — qoida

checked (Exception vorisi)

IOException
SQLException
FileNotFoundException
Kompilyator majbur qiladi: try/catch YOKI throws. Tashqi sabablar (fayl, tarmoq, baza) — kutilgan, tiklanishi mumkin.

unchecked (RuntimeException vorisi)

NullPointerException
IllegalArgumentException
ArithmeticException
IndexOutOfBounds
Majbur qilmaydi. Odatda dasturchi xatosi — ushlash emas, oldini olish kerak (null tekshirish, validatsiya).
03

Ko'tarilish — kim ushlaydi?

Xato chuqur metodda chiqsa, u chaqiruvchilar zanjiri bo'ylab yuqoriga ko'tariladi — kimdir catch qilguncha. Hech kim ushlamasa — stack trace bilan qulaydi.

04

try / catch / finally — tartib

Tartib.java
try {
    int x = 10 / 0;                     // 1) xato shu yerda
} catch (ArithmeticException e) {
    System.out.println("Nol'ga bo'lish");   // 2) ushlandi
} catch (Exception e) {              // umumiy — OXIRIDA (tor→keng)
    System.out.println("Boshqa xato");
} finally {
    System.out.println("Har doim");        // 3) xato bo'lsa ham, bo'lmasa ham
}
// multi-catch: catch (IOException | SQLException e) { ... }
tartib muhim
catch bloklari tordan kengga: avval ArithmeticException, keyin Exception. Teskari yozsangiz — kompilyatsiya xatosi ("already caught"), chunki keng catch hammasini yutib, tor catch'ga yetmaydi.
05

O'z exception'ingiz va chaining

Biznes xatolarini (masalan "balans yetarli emas") o'z exception'ingiz bilan ifodalang — kod o'qiladigan bo'ladi. Chaining — asl sababni (cause) yo'qotmasdan yangi exception'ga o'rash.

Custom.java
// o'z exception — RuntimeException'dan (unchecked, zamonaviy uslub)
public class YetarliEmasException extends RuntimeException {
    public YetarliEmasException(String msg) { super(msg); }
}

void yech(int s) {
    if (s > balans) throw new YetarliEmasException("Balans: " + balans);
}

// chaining — asl sababni saqlash
try { baza.saqla(); }
catch (SQLException e) {
    throw new SaqlashException("Saqlab bo'lmadi", e);  // e = cause
}
06

try-with-resources

Fayl, baza ulanishi kabi resurslarni yopish shart. try(...) qavsida ochsangiz, Java uni o'zi yopadi — xato bo'lsa ham. finallyda qo'lda yopish endi kerak emas.

Resource.java
try (var fayl = new FileReader("data.txt");
     var conn = dataSource.getConnection()) {   // bir nechta resurs
    // ishlaymiz
}   // Java ikkovini ham avtomatik yopadi (teskari tartibda) ✓
// Shart: resurs AutoCloseable bo'lishi kerak
07

Professional qoidalar

❌ xatoni yutish

catch (Exception e) {
  // hech narsa
}
Xato yo'qoladi, muammo yashirinadi. Kamida log qiling.

❌ hammasini ushlash

catch (Throwable t)
Error'larni ham yutadi (OOM). Faqat kerakli exception'ni ushlang.

✓ aniq va ma'noli

throw new YetarliEmasException(
  "Balans: " + balans);
Xabar tushunarli, tur aniq — debug oson.

✓ oqim boshqaruvi uchun EMAS

// if bilan tekshiring,
// exception bilan emas
Exception qimmat (stack trace). Kutilgan holatlarni if bilan hal qiling.
08

Suhbat savollari

?Checked va unchecked farqi, qachon qaysi?
Checked (Exception vorisi, RuntimeException emas) — kompilyator try/catch yoki throws talab qiladi; tashqi, tiklanadigan holatlar (IO, SQL). Unchecked (RuntimeException vorisi) — majburiy emas; dasturchi xatolari (NPE, IllegalArgument). Zamonaviy uslub: biznes xatolari uchun ham unchecked (Spring shunday).
?Error va Exception farqi?
Error — JVM darajasidagi jiddiy muammo (OutOfMemoryError, StackOverflowError), dastur tiklanolmaydi, ushlash ma'nosiz. Exception — dastur darajasidagi, ushlab tiklanishi mumkin bo'lgan holat.
?finally qachon ishlamaydi?
Deyarli doim ishlaydi — faqat System.exit() chaqirilsa yoki JVM qulasa (OOM, o'chirish) ishlamaydi. try'da return bo'lsa ham finally ishlaydi (return'dan oldin).
?throw va throws farqi?
throw — exception'ni otish (metod ichida, bitta obyekt). throws — metod imzosida "bu metod shu exception'ni chiqarishi mumkin" deb e'lon qilish (checked uchun majburiy). throw — harakat, throws — ogohlantirish.
?finally har doim bajariladimi?›
Deyarli: return, break, istisno bo‘lsa ham. Bajarilmaydi: System.exit(), JVM halokati, thread o‘ldirilishi, cheksiz sikl. finally’da return yozmang — istisnoni “yutib” yuboradi.
?Custom exception qachon checked, qachon unchecked?›
Zamonaviy amaliyot (Spring): asosan unchecked (RuntimeException) — biznes xatolari (MablagYetarliEmas) uchun; checked — chaqiruvchi haqiqatan tiklay oladigan holatlar uchun. Spring @Transactional checked’da rollback qilmaydi (30-dars).
?Istisnoni qanday to‘g‘ri log qilasiz va qayta tashlaysiz?›
Sababni saqlang: throw new XizmatXatosi("…", e) (cause). Bitta joyda log qiling (log-and-throw anti-pattern — takror loglar). catch (Exception e) {} — hech qachon bo‘sh qoldirmang.
