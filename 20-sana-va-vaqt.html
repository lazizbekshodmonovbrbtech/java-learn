Sana va vaqt java.time

Bank tizimida sana hamma joyda: tranzaksiya vaqti, kredit muddati, foiz kunlari, hisobot davri. Vaqt oddiy ko'rinadi, lekin timezone, DST, oy uzunligi — eng ko'p bug shu yerdan chiqadi. Bu modul sizni o'sha tuzoqlardan olib o'tadi.

01

Nega eski Date yomon edi?

Java 8'gacha java.util.Date va Calendar ishlatilardi. Ular hozir ham kodda uchraydi — bilish shart, lekin yangi kodda ishlatmang.

❌ java.util.Date (1996)

• Oy 0'dan boshlanadi: new Date(2024, 0, 15) = 15-yanvar
• Mutable — setTime() bilan o'zgaradi, thread-safe emas
• Timezone haqida hech narsa bilmaydi, lekin toString() lokal zonada chiqaradi
• SimpleDateFormat ham thread-safe emas — ko'p thread'da noto'g'ri sana!

✅ java.time (Java 8+, JSR-310)

• Immutable — har amal yangi obyekt qaytaradi, thread-safe
• Oy 1'dan: Month.JANUARY = 1
• Har tushuncha alohida tip: sana, vaqt, lahza, zona
• DateTimeFormatter thread-safe, static final qilib saqlash mumkin

⚠ Immutable degani
date.plusDays(1); — hech narsa o'zgarmaydi! Natijani olish shart: date = date.plusDays(1);. Bu String'dagi kabi.
02

Bir lahza — to'rt soat

Eng muhim g'oya: Instant — dunyodagi bitta aniq lahza (UTC'da). ZonedDateTime — o'sha lahzaning ma'lum bir shahardagi ko'rinishi. Slayderni suring: lahza bitta, soatlar har xil.

Instant = 2024-03-15T07:00:00Z  (UTC, "Z" = zero offset)
15-mart 00:00 UTC16-mart 23:00 UTC
Zones.java
Instant lahza = Instant.now();                // UTC, hamma uchun bir xil
ZonedDateTime tosh = lahza.atZone(ZoneId.of("Asia/Tashkent")); // +05:00
ZonedDateTime lond = lahza.atZone(ZoneId.of("Europe/London"));
// tosh.toInstant().equals(lond.toInstant()) → true — bir lahza!
// tosh.toLocalTime().equals(lond.toLocalTime()) → false — soat har xil
💡 Qoida
Serverda va bazada Instant/UTC saqlang. Faqat foydalanuvchiga ko'rsatishda uning zonasiga aylantiring. "Tashkent vaqtida saqlaymiz" — keyin Londonda filial ochilsa hammasi buziladi.
03

Tiplar narvoni: har biri nimani biladi?

java.time'da har tip aniq bir savolga javob beradi. Ustiga bosing — nimani bilishi va bilmasligini ko'ring.

Tipga bosing.
🎯 Suhbatda
"LocalDateTime va ZonedDateTime farqi?" — LocalDateTime zona bilmaydi: "15-mart 09:00" — qayerda? Noma'lum. Uni Instant'ga aylantirib bo'lmaydi (zona bermasangiz). ZonedDateTime = LocalDateTime + ZoneId — aniq lahza.
04

Period vs Duration — ikki sana orasi

Period — inson tilida: "2 yil 3 oy 5 kun" (kalendar). Duration — mashina tilida: soniyalar. Kredit muddati uchun Period, SLA/timeout uchun Duration. Sanalarni o'zgartirib ko'ring.

Period.between(d1, d2)
Duration / ChronoUnit.DAYS
Kredit.java
LocalDate berilgan = LocalDate.of(2024, 1, 15);
LocalDate tugash = berilgan.plusMonths(12);            // 2025-01-15
Period muddat = Period.between(berilgan, tugash);     // P1Y (1 yil)
long kunlar = ChronoUnit.DAYS.between(berilgan, tugash); // 366 (2024 — kabisa!)

// Foiz hisobi: kunlik foiz × kunlar soni — shuning uchun DAYS.between kerak
Duration timeout = Duration.ofSeconds(30);        // HTTP timeout uchun
// 31-yanvar + 1 oy = 28/29-fevral (oxirgi kunga "yopishadi"), 31-mart emas!
LocalDate.of(2024,1,31).plusMonths(1); // → 2024-02-29

Format.java
private static final DateTimeFormatter F = DateTimeFormatter.ofPattern("dd.MM.yyyy HH:mm");

String s = LocalDateTime.now().format(F);            // "15.03.2024 09:05"
LocalDateTime t = LocalDateTime.parse("15.03.2024 09:05", F);
LocalDate d = LocalDate.parse("2024-03-15");              // ISO — formatter shart emas
// Noto'g'ri matn → DateTimeParseException (unchecked) — try/catch qiling
⚠ Klassik xato
"dd.mm.yyyy" — kichik mm bu minut. Natija: 15.05.2024 chiqadi (05 = minut) va hech kim sezmaydi. Yana: YYYY (katta) — "week-based year", yil oxirida noto'g'ri yil beradi. Doim yyyy.
06

DST tuzog'i — yo'qolgan va ikkilangan soat

Yozgi vaqtga o'tadigan mamlakatlarda (Yevropa, AQSh) yilda bir marta bir soat yo'q, bir marta bir soat ikki marta keladi. O'zbekistonda DST yo'q, lekin xalqaro o'tkazmalarda uchraydi. Rejimni tanlang.

Dst.java
ZoneId ldn = ZoneId.of("Europe/London");
ZonedDateTime t = ZonedDateTime.of(2024,3,31, 1,30,0,0, ldn);
t.plusHours(1);   // 03:30 — 02:30 mavjud emas, sakraydi

// Shuning uchun: "har kuni 02:30 da" cron — DST kunida ishlamasligi mumkin!
// Xavfsiz: Instant bilan hisoblang, keyin zonaga aylantiring.

08

Suhbat savollari

?Instant, LocalDateTime, ZonedDateTime farqi?›
Instant — UTC'dagi aniq lahza (epoch'dan nanosekund). LocalDateTime — zonasiz "devordagi soat" (15-mart 09:00 — qayerda, noma'lum). ZonedDateTime — LocalDateTime + ZoneId, ya'ni aniq lahza + qoidalar (DST). Saqlash: Instant. Ko'rsatish: ZonedDateTime.
?Nega java.util.Date o'rniga java.time?›
Date mutable va thread-safe emas, oy 0'dan, SimpleDateFormat ham thread-safe emas (ko'p thread'da noto'g'ri natija), zona tushunchasi chalkash. java.time immutable, aniq tiplar, thread-safe formatter, ISO-8601 default.
?Period va Duration farqi?›
Period — kalendar birliklarda (yil/oy/kun), LocalDate bilan. Duration — soniya/nano, vaqt asosida, Instant/LocalTime bilan. "1 oy" Period'da o'zgaruvchan (28–31 kun), Duration'da esa aniq soniya.
?Bazada vaqtni qanday saqlaysiz?›
UTC'da, timestamptz ustunida, Java tomonda Instant (yoki OffsetDateTime). JVM va DB timezone'ni UTC qilib qo'yaman, ko'rsatishda foydalanuvchi zonasiga aylantiraman. LocalDateTime ni timestamp'ga saqlash — zona yo'qoladi, migratsiyada muammo.
?Testda "hozir"ni qanday nazorat qilasiz?›
java.time.Clock ni dependency sifatida beraman. Prod'da Clock.systemUTC(), testda Clock.fixed(Instant.parse("..."), ZoneOffset.UTC). Shunda "kredit muddati o'tganmi" kabi logika deterministik testlanadi.
?DateTimeFormatter thread-safe'mi?›
Ha — immutable, static final qilib bitta nusxa saqlash to'g'ri. Eski SimpleDateFormat esa yo'q — uni har chaqiriqda yangi yaratish yoki ThreadLocal kerak edi.
