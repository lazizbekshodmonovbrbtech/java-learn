equals va hashCode

Ikki obyekt qachon "teng"? HashMap ularni qanday tez topadi? Bu — suhbatning eng texnik va eng ko'p adashtiradigan mavzusi. Jonli bucket demo bilan tushunamiz.

01

Muammo: bir xil ma'lumot, ikki obyekt

Ikki User obyekti bir xil ma'lumotga ega (id=1, "Ali"), lekin xotirada alohida. Ular "teng"mi? Bu siz nima deb hisoblashingizga bog'liq. equals() qayta yozilganmi — almashtiring.

User
id=1, "Ali"@0x50
vs
User
id=1, "Ali"@0x88
User.java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof User u)) return false;
    return id == u.id && ism.equals(u.ism);  // mazmun bo'yicha
}
02

HashMap obyektni qanday topadi

HashMap juda tez (o'rtacha O(1)) — chunki u hashCode() orqali qaysi "bucket"ga qo'yishni hisoblaydi, keyin equals() bilan aynan o'shanimi tekshiradi. Kalit qo'shing va qidiring — jarayonni kuzating.

hashCode() qayta yozilgan:
Ha ✓
Kalit yozing va put() bosing. Keyin get() bilan qidiring.
hashCode'ni o'chirib ko'ring
Yuqoridagi tugmani "Yo'q" ga o'tkazing — hashCode qayta yozilmagan holat. Bir xil kalitni put qilib, get qilsangiz — HashMap uni topolmaydi! Chunki har obyekt boshqa hashCode oladi → boshqa bucketga tushadi → get boshqa bucketga qaraydi.
03

Kontrakt — oltin qoida

equals va hashCode doim birga qayta yoziladi. Ular o'rtasida qat'iy shartnoma bor:

equals/hashCode kontrakti

1. Ikki obyekt equals() bo'yicha teng bo'lsa, ularning hashCode()'i ham teng bo'lishi SHART.

2. hashCode teng bo'lsa, equals teng bo'lishi shart emas (turli obyekt bir bucketga tushishi mumkin — collision).

3. Bir obyekt uchun hashCode o'zgarmasligi kerak (shuning uchun immutable maydonlardan hisoblanadi).

eng ko'p so'raladi
"equals'ni qayta yozdim, hashCode'ni yozmasam nima bo'ladi?" — obyekt HashMap/HashSet'da yo'qoladi: put qilganingizni get topolmaydi, chunki teng obyektlar turli bucketga tushadi. Doim ikkovini birga yozing (IDE bir tugmada yaratadi).
04

Immutability va record

hashCode barqaror bo'lishi uchun obyekt immutable bo'lgani ma'qul. Java 14+ da record — immutable data class'ni bir qatorda yaratadi va equals/hashCode/toString'ni avtomatik beradi.

Record.java
// oddiy class'da ~40 qator kerak edi. record'da:
public record User(int id, String ism) {}

// avtomatik oladi:
//   equals() — mazmun bo'yicha ✓
//   hashCode() — mos ✓
//   toString() — chiroyli ✓
//   getterlar: id(), ism() ✓
//   immutable (final maydonlar) ✓
amalda
Oddiy ma'lumot tashuvchi class'lar (DTO, kalitlar) uchun record ishlating — equals/hashCode'ni qo'lda yozish xatolarini yo'q qiladi. record'lar 21-modulda batafsil.
05

Suhbat savollari

?equals va hashCode nega birga qayta yoziladi?
Kontrakt tufayli: teng obyektlar (equals) bir xil hashCode berishi shart. Faqat equals'ni yozsangiz, HashMap/HashSet buziladi — teng obyektlar turli bucketga tushib, get topolmaydi. Ikkovi bir-birini to'ldiradi.
?HashMap obyektni qanday topadi?
Ikki bosqich: (1) hashCode() orqali qaysi bucketga qarashni hisoblaydi (hash % bucket soni); (2) o'sha bucketda equals() bilan aynan mos kalitni topadi. Shuning uchun ikkovi ham to'g'ri bo'lishi kerak. O'rtacha O(1).
?== va equals farqi (yana)?
== obyektlarda manzilni (bir xil obyektmi) solishtiradi. equals() mazmunni — lekin faqat qayta yozilgan bo'lsa (aks holda u ham manzilni solishtiradi, chunki Object'dagi standart shunday). Shuning uchun mazmun uchun equals'ni override qilasiz.
?hashCode nega immutable maydonlardan hisoblanishi kerak?
Agar obyekt HashMap'ga qo'yilgach hashCode'i o'zgarsa (o'zgaruvchan maydondan hisoblangani uchun), u boshqa bucketga tegishli bo'lib qoladi va topilmaydi. Shuning uchun hashCode barqaror (o'zgarmas) maydonlardan hisoblanadi — record bu muammoni yo'q qiladi.
