Spring Security va JWT

Bank API'sida har so'rov "sen kimsan?" va "senga mumkinmi?" savolidan o'tadi. Spring Security buni filter zanjiri orqali qiladi. JWT — bu "men kimligimni tasdiqlovchi imzolangan pasport". Ikkalasini ham ko'z bilan ko'ramiz.

01

Ikki savol: Authentication va Authorization

🪪 Authentication — "Sen kimsan?"

Login+parol, JWT, OAuth2 orqali shaxsni aniqlash. Natija: Authentication obyekti (principal + authorities), SecurityContextHolder'da saqlanadi. Xato → 401 Unauthorized.

🔑 Authorization — "Senga mumkinmi?"

Aniqlangan foydalanuvchining huquqi bormi: rol (ADMIN), authority (TRANSFER_CREATE), egalik (o'z hisobimi?). Xato → 403 Forbidden.

🎯 Suhbatda
"401 va 403 farqi?" — 401: kim ekaningiz noma'lum (token yo'q/yaroqsiz). 403: kimligingiz ma'lum, lekin ruxsat yo'q. Ko'pchilik chalkashtiradi — siz chalkashtirmang.
02

Filter zanjiri — so'rov qanday o'tadi

Spring Security controller'gacha bir qator servlet filter qo'yadi. So'rov har biridan navbat bilan o'tadi; istalgan filter uni to'xtatishi mumkin. Ssenariyni tanlab, "Yubor"ni bosing.

Natija shu yerda
So'rov yuqoridan pastga filter'lardan o'tadi. Yashil — o'tdi, qizil — shu yerda to'xtadi.
03

JWT anatomiyasi — bosing, o'zgartiring, buzing

JWT = header.payload.signature. Header va payload — shunchaki Base64 (hech kim shifrlamagan — hamma o'qiy oladi!). Imzo — header+payload'ni maxfiy kalit bilan HMAC qilgan natija. Payload'dagi rolni o'zgartirib ko'ring — imzo mos kelmay qoladi.

⚠ Eng muhim 3 qoida
1) Payload'ga parol, karta raqami yozmang — u ochiq. 2) Token qisqa muddatli (5–15 min) + refresh token. 3) Maxfiy kalit uzun (≥256 bit), env/vault'da, kodda emas. JWT'ni "bekor qilib" bo'lmaydi — muddati tugaguncha yaroqli; shuning uchun qisqa muddat.

  


  

    
04
Login oqimi — token qayerdan keladi

    

      

      

      

    

    

      
SecurityConfig.java

      
@Configuration @EnableMethodSecurity
public class SecurityConfig {
    @Bean
    SecurityFilterChain chain(HttpSecurity http, JwtAuthFilter jwt) throws Exception {
        return http
            .csrf(c -> c.disable())                              // stateless API — cookie yo'q, CSRF kerak emas
            .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/api/auth/**").permitAll()       // login ochiq
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())                   // qolgani — token shart
            .addFilterBefore(jwt, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
    @Bean PasswordEncoder encoder() { return new BCryptPasswordEncoder(); }
}

// JwtAuthFilter — har so'rovda bir marta
protected void doFilterInternal(req, res, chain) {
    String h = req.getHeader("Authorization");
    if (h != null && h.startsWith("Bearer ")) {
        Claims c = jwtService.parse(h.substring(7));   // imzo + muddat tekshiriladi
        var auth = new UsernamePasswordAuthenticationToken(c.getSubject(), null, rollar(c));
        SecurityContextHolder.getContext().setAuthentication(auth);   // "sen kimsan" javobi
    }
    chain.doFilter(req, res);
}

    

  


  

    
05
Parol hech qachon ochiq saqlanmaydi

    
BCrypt — sekin, tuzlangan (salt) hash. Bir xil parol ikki marta — ikki xil hash. Yozib ko'ring, keyin "Qayta hash"ni bosing.

    

      

      

      
$2a$ — BCrypt versiyasi · 10 — cost (2¹⁰ iteratsiya, ~100 ms; brute-force'ni sekinlashtiradi) · 22 belgi salt · qolgani hash. Tekshiruv: encoder.matches(kiritilgan, bazadagiHash) — salt hash ichida, shuning uchun solishtira oladi. MD5/SHA-256 parol uchun yaramaydi — juda tez (GPU: milliardlab/soniya).

Rol vs Authority
hasRole("ADMIN") aslida hasAuthority("ROLE_ADMIN") — Spring ROLE_ prefiksini o'zi qo'shadi. Rol — kim (ADMIN, OPERATOR). Authority — nima qila oladi (TRANSFER_CREATE). Katta tizimda authority'lar aniqroq.

      
CORS vs CSRF
CORS — brauzer boshqa domen'dan so'rovga ruxsat beradimi (frontend localhost:3000 → api). CSRF — cookie-session'ga hujum; stateless JWT API'da (cookie yo'q) o'chiriladi. JWT cookie'da saqlansa — CSRF yana kerak!

    

  


  

    
07
Suhbat savollari

    

      
?Spring Security qanday ishlaydi (yuqori darajada)?›
Servlet filter zanjiri: DelegatingFilterProxy → FilterChainProxy → SecurityFilterChain (bir nechta filter). Autentifikatsiya filter'i Authentication yaratib SecurityContextHolder'ga (ThreadLocal) qo'yadi. Oxirida AuthorizationFilter qoidalarni tekshiradi. Xatolar ExceptionTranslationFilter'da 401/403'ga aylanadi.

      
?JWT nima, sessiyadan farqi?›
Session: server holatni saqlaydi (xotira/Redis), mijozda faqat ID (cookie). JWT: holat tokenning o'zida, imzolangan — server hech narsa saqlamaydi (stateless, gorizontal scaling oson). Kamchilik: bekor qilib bo'lmaydi (blacklist/qisqa muddat + refresh kerak), hajmi katta, payload ochiq.

      
?JWT imzosi nima kafolatlaydi? Shifrlaydimi?›
Faqat butunlik va manba — o'zgartirilmagan va bizning kalit bilan imzolangan. Maxfiylikni emas — payload Base64, hamma o'qiydi. Maxfiy ma'lumot kerak bo'lsa JWE (shifrlangan) yoki payload'ga yozmaslik.

      
?Access va refresh token nima uchun ikkita?›
Access — qisqa (5–15 min), har so'rovda yuboriladi, o'g'irlansa zarar cheklangan. Refresh — uzoq (kunlar), faqat yangi access olish uchun, bazada saqlanadi va bekor qilinishi mumkin (logout, shubhali faoliyat). Ikkalasi bilan xavfsizlik + qulaylik.

      
?Nega BCrypt, SHA-256 emas?›
SHA-256 tez — GPU'da milliardlab urinish/soniya, lug'at hujumi oson. BCrypt/Argon2 ataylab sekin (cost) va salt'li — bir xil parol har xil hash, rainbow table ishlamaydi. Cost'ni vaqt o'tib oshirish mumkin.

      
?SecurityContextHolder qayerda saqlanadi? Async'da nima bo'ladi?›
Default — ThreadLocal, ya'ni joriy thread'da. @Async yoki yangi thread'da yo'qoladi. Yechim: DelegatingSecurityContextExecutor yoki MODE_INHERITABLETHREADLOCAL. Virtual thread'larda ham shu qoida.

      
?OAuth2 / OpenID Connect va JWT bog'liqligi?›
OAuth2 — avtorizatsiya protokoli (kimga qanday ruxsat), OIDC — uning ustida autentifikatsiya qatlami (id_token). JWT — token formati; OAuth2 access token ko'pincha JWT bo'ladi. Bankda: Keycloak kabi Authorization Server, Spring — Resource Server (oauth2ResourceServer().jwt()) — tokenni JWKS public key bilan tekshiradi.
