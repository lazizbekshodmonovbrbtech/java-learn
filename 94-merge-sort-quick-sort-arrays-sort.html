Bo‘lib-hukmronlik: merge sort va quick sort

93-darsdagi saralashlar O(n²) — 1 mln tranzaksiya uchun soatlar. Tezlik siri: masalani yarmiga bo‘lish, har yarmini alohida yechish va natijalarni birlashtirish. Shunday qilib n log n ga tushamiz — 1 mln element uchun ~20 mln qadam, millisekundlar. Oxirida Java’ning Arrays.sort ichida aslida nima borligini ko‘ramiz.

01

Merge sort: bo‘l, sarala, birlashtir

Avval massiv bitta elementgacha bo‘linadi (bitta element — doim saralangan!). Keyin juftlab birlashtiriladi: ikki saralangan qatordan har safar kichigini olamiz.

Kirish:
MergeSort.java
  1. static void sort(int[] a, int lo, int hi, int[] tmp) {
  2. if (hi - lo < 1) return; // 1 ta element
  3. int mid = (lo + hi) / 2;
  4. sort(a, lo, mid, tmp); // chap yarim
  5. sort(a, mid + 1, hi, tmp); // o‘ng yarim
  6. int i = lo, j = mid + 1, k = lo;
  7. while (i <= mid && j <= hi) // birlashtirish
  8. tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
  9. while (i <= mid) tmp[k++] = a[i++];
  10. while (j <= hi) tmp[k++] = a[j++];
  11. for (k = lo; k <= hi; k++) a[k] = tmp[k];
  12. }
Nega n log n?
Massiv har safar ikkiga bo‘linadi → log₂ n daraja (8 element → 3 daraja, 1 mln → 20). Har darajada hamma elementlar bir marta birlashtiriladi → n ish. Jami n × log n. Eng yomon holat ham shunday — ma’lumotga bog‘liq emas. Narxi: O(n) qo‘shimcha xotira (tmp).
02

Quick sort: pivot atrofida bo‘lish

Bitta elementni pivot qilib olamiz. Undan kichiklar chapga, kattalar o‘ngga. Endi pivot o‘z joyida — qolgan ikki qism uchun takrorlaymiz. Qo‘shimcha massiv kerak emas.

Kirish:
QuickSort.java
  1. static void quick(int[] a, int lo, int hi) {
  2. if (lo >= hi) return;
  3. int pivot = a[hi], i = lo; // Lomuto bo‘linishi
  4. for (int j = lo; j < hi; j++) {
  5. if (a[j] < pivot) {
  6. swap(a, i, j);
  7. i++;
  8. }
  9. }
  10. swap(a, i, hi); // pivot o‘z joyiga
  11. quick(a, lo, i - 1);
  12. quick(a, i + 1, hi);
  13. }
Quick sort’ning zaif nuqtasi
Pivot har safar eng katta (yoki eng kichik) bo‘lsa — bo‘linish 0 va n−1 bo‘ladi → O(n²) va chuqur rekursiya. "Saralangan" misolni sinab ko‘ring. Yechimlar: tasodifiy pivot, "uchtaning medianasi", va juda chuqurlashsa heap sort’ga o‘tish (introsort).

06

Suhbat savollari

?Merge sort va quick sort farqi? Qaysi birini qachon?›
Merge: doim O(n log n), barqaror, O(n) qo‘shimcha xotira; bog‘langan ro‘yxat va tashqi (diskdagi) saralash uchun yaxshi. Quick: o‘rtacha O(n log n) va amalda tezroq (keshga mos, joyida), lekin eng yomon O(n²), barqaror emas. Shuning uchun Java primitivlarga quick (dual-pivot), obyektlarga barqaror TimSort ishlatadi.
?Quick sort eng yomon holati qachon va qanday oldi olinadi?›
Pivot doim chetdagi qiymat bo‘lsa (saralangan massiv + oxirgi elementni pivot qilish) — bo‘linish nosimmetrik, O(n²). Tasodifiy pivot, median-of-three, ko‘p dublikat uchun 3-yo‘lli bo‘linish (Dutch flag), introsort (chuqurlik limitida heap sort).
?Merge sort xotira murakkabligi?›
Massiv uchun O(n) yordamchi buffer + O(log n) rekursiya steki. Bog‘langan ro‘yxatda birlashtirish ko‘rsatkichlarni ulash bilan — O(1) qo‘shimcha (stekdan tashqari).
?Counting/radix sort qachon O(n log n) dan tez?›
Kalitlar butun son va oralig‘i k kichik bo‘lsa: counting O(n + k). Radix — raqamlar bo‘yicha d marta counting: O(d·(n + b)). Taqqoslash chegarasi Ω(n log n) ularga taalluqli emas, chunki ular taqqoslamaydi.
?Comparator’da a - b yozish nega xavfli?›
int overflow: katta musbat va katta manfiy sonlar ayirmasi chegaradan oshib, ishora o‘zgaradi — tartib buziladi. Integer.compare(a, b) yoki Comparator.comparingInt ishlatish kerak. BigDecimal uchun compareTo.
